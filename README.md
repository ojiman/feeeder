# Feeeder

macOS 26.6以降向けのSwiftUI / SwiftData製RSSリーダー。Backendを持たないローカルファースト構成です。現在は、フィードXMLを手動で取り込めるローカル開発版で、購読・既読・LikeをMacに保存します。

## 起動

XcodeのSwiftツールチェーンで、プロジェクトルートから実行します。追加パッケージは不要です。

```sh
bash scripts/build-app.sh
```

生成される `.build/RSS Reader.app` をFinderから開いてください。コンパイラの中間出力は `/private/tmp/rss-reader-build` に置きます。

## 操作

- 左から購読元・記事一覧・本文の3カラム。
- 一覧にフォーカスした状態で `j` / `k` による記事移動。
- 記事を選ぶと既読。`m` で既読／未読を切り替え、`s` でLikeを切り替え。
- ツールバーからシステム追従・ライト・ダークを選択。
- 既読状態とLikeの掲載サイト・日時はSwiftDataに保存。
- 左上の「＋」からフィードURLとXMLを入力して取り込み。メニューで合成RSS 1.0 / RSS 2.0 / Atomを入力できます。
- 同じフィードURLのXMLを再取り込みすると更新。購読名の変更は保持します。
- 購読元を右クリックすると、名前・1階層フォルダの編集と購読解除ができます。解除後も記事・本文・Likeは残ります。
- 元URLがある記事では `b` で外部ブラウザ、`v` でアプリ内WebKitを開き、`Esc` または「記事に戻る」で戻ります。この操作は指定サイトへ通信します。

合成サンプルの `.example` URLには実在ページがありません。サンプルでは取り込み・整理・重複防止を試してください。RSS 2.0とRSS 1.0のサンプルは同じ記事URLを共有し、両方を追加しても記事数は1件だけ増えます。

保存先はアプリ専用のApplication Support内 `RSSReader-Development/Reader.store` です。検証時は `--data-directory <path>` で別の保存先を指定できます。V1では専用保存先 `Application Support/Feeeder/Reader.store` の空ライブラリから開始し、プロトタイプのデータを引き継ぎません。

フィードの自動取得・本文抽出・AI要約は未実装です。「フィード本文」は提供された範囲であり、全文取得済みを意味しません。ページ閲覧はこの開発段階では非永続セッションで、ログイン状態を保持しません。Keychainアクセスは行いません。

## 検証

```sh
swift test --scratch-path /private/tmp/rss-reader-build
```

テストは合成XMLと専用の一時ストアだけを使用します。解析、名前空間・日時・相対URL、エンティティ拒否、重複防止、本文更新、購読編集、解除後のLike保持、ディスクストア再作成、キーボード選択と元ページURLの状態を検証します。

2026-09-09: 自動テスト15件成功。画面から合成RSSを取り込み、記事6→7件、本文表示・既読・Like、購読名変更・フォルダ設定を確認しました。アプリを終了して再起動し、7記事・Like1件・変更した購読名とフォルダが残ることも確認済みです。b/v/Escの実サイトでの操作、1万記事での応答時間・連続スクロールの滑らかさ・ブラウザから戻る際のフォーカスとスクロール復元は未測定・未確認です。

V1の製品要件は [PRD](docs/specification.md)、技術設計とエージェント実行ハーネスは [Architecture](docs/architecture.md) を参照してください。現行の試作品にはLike操作が残っていますが、V1では専用Likeを使わず、記事を開いた既読状態から週ごとのノートを作る方針です。本開発版はV1の受入条件を満たしていません。独立した性能・実サイト・外部AIハンドオフの検証は未実施です。
