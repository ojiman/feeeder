# Feeeder

macOS 26.6以降向けのRSSリーダー。SwiftUI / AppKitで表示し、SwiftDataへ端末内保存します。アカウント・Backend・同期はありません。Star・日次スクラップ・週ノート・フォルダ・画像表示を実装しています。実機受入と最終PdM判断は継続中です。

## 起動

XcodeのSwiftツールチェーンで、プロジェクトルートから実行します。SwiftPMが固定版のSwiftSoup 2.13.9を解決します。

```sh
bash scripts/build-app.sh release
```

生成される `.build/Feeeder.app` をFinderから開いてください。ad hoc署名されたローカル開発用アプリです。Developer ID署名・公証は行いません。releaseの中間出力は `/private/tmp/feeeder-v1-release`、debugは `/private/tmp/rss-reader-build` に置きます。debug buildは引数を省略できます。

通常起動は空ライブラリから開始します。V1の保存先は `Application Support/Feeeder/Reader.store`。同じ版での再起動では購読・記事・既読日時・ノートを保持します。ベータ中はバージョン更新をまたぐデータ保持を保証せず、1.0以降は保証します。旧スキーマのDBは開けない場合があります。初期化がエラーを返した場合は「ライブラリを開けませんでした」と表示し、アプリによる自動削除・作り直しは行いません。非互換スキーマでのSwiftDataの挙動は未検証です。ベータ配布時のリリースノートにもこの制約を記載します。過去のリリースノートの保持検証は、その版での結果であり、以後のベータ間の互換性保証ではありません。プロトタイプのデータ移行はありません。

ベータの更新後に開けず、新しい空ライブラリで使い直す場合は、本人の操作で次のように退避します。この手順自体の実機確認は未実施です。

1. Feeederを⌘Qで終了します。
2. Finderの「移動 → フォルダへ移動」で `~/Library/Application Support/` を開きます。
3. `Feeeder`フォルダ全体を、例えば`Feeeder-backup-20261007-2100`へ名前変更して残します。`Reader.store`と、存在する場合の`Reader.store-shm`／`Reader.store-wal`は同じ組として退避し、DBファイルだけを抜き出さないでください。フォルダにはノートやHandoffの管理データも含まれます。
4. Feeederを起動すると、新しい`Feeeder`フォルダと空ライブラリを作ります。退避したフォルダは確認が済むまで残してください。退避はデータの変換・復元を保証するものではありません。

合成デモは保存先と挿入を明示して起動します。

```sh
open '.build/Feeeder.app' --args --data-directory /private/tmp/feeeder-demo --seed-demo
```

`--data-directory <path>` は開発検証用の保存先指定です。合成デモの `.example` URLに実在ページはありません。実際の購読・記事・ノートをGitへ追加しないでください。

## 操作

- 左はFeeds／Notesの対象切替、中央は記事／ノート一覧、右は読書／ノート編集の3カラム。外観はシステム追従・ライト・ダークから選べます。
- 左カラム右上の「＋」へRSS/Atom URLを入力し、未分類・既存フォルダを選ぶか、新しいフォルダ名を入力して購読。その右隣が更新ボタンです。手動XMLと合成サンプルも取り込めます。購読の右クリックで名前・1階層フォルダ・移動・解除を操作します。フォルダ選択で配下の記事を集約し、フォルダの右クリックで名前変更・統合ができます。
- 起動・復帰・稼働中30分ごとに更新し、ツールバーから手動更新できます。通信失敗でも保存済み記事を読み続けられます。
- 一覧にフォーカスして `j` / `k` で移動、`m` で既読／未読を切り替えます。一覧のスクロールでは既読にせず、本文またはRSS要約の実表示で初回既読日時を記録します。
- `s`でStarを付け外し、Star一覧から読み返せます。`n`で当日の既定ノートへタイトル・URL・保持中のRSS要約を保存します。同日の再保存は重複・上書きせず、全文は複製しません。右上のボタンでも同じ操作ができます。
- `b` で外部ブラウザ、`v` でアプリ内の原文、`Esc` で読書へ戻ります。原文閲覧は指定サイトへ通信し、アプリ内ブラウザはログイン状態を保存しません。原文中も`j/k/s/n`を使え、入力欄と修飾キー付きの操作を優先します。
- 本文抽出はbest effortです。「フィード提供本文」「抽出本文・全文保証なし」「RSS要約のみ」を区別します。取得不可なら要約と原文リンクを残し、制限を回避する取得は行いません。
- 「日次ノート」で本文と各スクラップのメモを編集できます。最初の保存時に日・Timezoneを固定し、保存済み要約は記事の期限後も残ります。
- 「週の振り返り」から週ノートを編集できます。前週を先に表示し、現在週は下書き。同じ週に複数ノートを作れます。初回ノート作成時の期間・Timezoneを保存し、以後も同じ範囲を使います。Starの付与日時とスクラップ保存日時を週候補に使い、既読履歴も確認できます。採用時は出典と保存済み要約を週ノートへコピーし、日次本文やメモは自動コピーしません。
- 一覧にFaviconと利用可能な記事サムネイル、本文上に画像を表示します。画像はベストエフォートで、取得中・失敗でも表示枠の高さを変えません。キャッシュは64MiB、成功7日・失敗10分、同時取得4件までです。
- 記事本文・RSS要約は初期30日、Settingsで7 / 30 / 90 / 365日へ変更できます。未読は初回受信、既読は初回既読が起算点。保持短縮・本文一括削除は対象を確認して実行します。ノート・出典・明示保存した要約は自動削除しません。Starは本文の期限を延長しません。

## Claude Desktop連携

記事・日次ノート・週ノートから「AI入力を確認」を開きます。出力言語と出典を選び、保存済みRSS要約と保持中の記事を区別して、省略のない全文・カバー範囲・出典URLをレビューして「Claudeで開く」を操作します。

確認対象は **Claude Desktop 2.19675.0 / Pro / Cowork**。通常Chatへの自動添付、他版・他プランは未検証です。アプリは短い依頼文とTXTのパスを起動リンクへ渡し、記事本文はTXT内に保持します。

Claude側の **Attach確認** と **本人による送信** が必要です。送信後に別のフォルダ許可が出る場合があります。この許可はフォルダ内の読取り・変更を可能にし、cloudで使われるファイルは端末を離れます。Feeederは生成パッケージと管理metadataだけを専用フォルダに置きます。リンク由来の依頼文に注意表示が出る場合もあります。起動成功は、添付完了・送信・読取り成功を意味しません。

取消・起動失敗時は同じレビュー内容で再試行でき、全文コピー・TXT書き出しも使えます。制限時は1MiB以下のUTF-8分割ファイルを書き出せます。この分割サイズはClaudeの対応上限を示す値ではありません。

アプリ管理コピーは生成から24時間まで保持します。保持中の記事を含む場合は元本文の最早期限も上限です。保存済み要約だけの場合は元記事の期限では失効しません。保持短縮・本文削除にも同期します。本人が指定した書き出し先と、Claude側に渡った内容はこの削除の対象外です。返答を読んでノートへ貼り付け、出典を採用する操作は本人が行います。自動送信・返答の自動書込みはありません。

## 検証と仕様

```sh
swift test --scratch-path /private/tmp/feeeder-dogfooding-build
```

ベータ中のCIは回帰テストとReleaseビルドの2並列です。`docs/**`またはMarkdownだけの変更ではCIを省略します。CIのZIPはad hoc署名された開発ビルドで、Developer ID署名・公証・自動Release公開を行わず、配布済みベータのZIPとは異なります。CIのビルドをMacで試すときは、ブラウザで保存せず `bash scripts/fetch-ci-app.sh <PR番号>` を使ってください（macOSと、ログイン済みの最近の`gh`が必要です）。ブラウザで保存したファイルには隔離属性が付き、公証のないアプリはビルドのたびにmacOSに止められます。`gh`で取得すると付かず、PRのheadと一致するビルドかを確認し、署名を検証し、合成データ用の起動コマンドを表示します。ブラウザで保存した場合に止められたときは、システム設定の「プライバシーとセキュリティ」から「このまま開く (Open Anyway)」を選んでください。管理者パスワードが必要です。ベータ間の保持検証はCIの対象外で、通常の`swift test`ではfixture未指定の保持試験だけスキップします。手動で検証する場合は次を実行します。

```sh
bash scripts/prepare-v1-store-fixture.sh /private/tmp/feeeder-v1-fixture-new
FEEEDER_V1_FIXTURE_DIR=/private/tmp/feeeder-v1-fixture-new swift test --scratch-path /private/tmp/feeeder-dogfooding-build
```

fixture生成先は存在しないディレクトリを指定します。配布済みベータの固定commitで合成DBを作り、新スキーマで開いて保持を検証します。1.0出荷時にはスキーマを`VersionedSchema`として固定し、1.0リリースタグを起点とする保持検証をCIへ組み込みます。テストは合成RSS/HTMLと一時DBを使います。[PRD](docs/specification.md)、[Architecture](docs/architecture.md)、[今回の受入記録](docs/verification/2026-10-07-dogfooding-acceptance.md)に仕様・検証結果・未確認事項を記録しています。macOS 26.6での実機動作、Reeder Classicを参考にした操作感のPdM判断、V1全体の受入は未完了です。
