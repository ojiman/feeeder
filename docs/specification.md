## 1. 目的と対象利用者

**提供価値と対象利用者**は[ビジョン](vision.md)（英語。オーナーの言葉）に固定してある。要約: 量産される記事の中から本当に重要な記事を見つけ、自分の価値に変える。対象は2026年のITエンジニア。読む・メモする・理解するのループ（AIへの相談は、システムのWriting Toolsと、ノートのコピーで。決定0049。ビジョンの文言は、これに合わせて、オーナーが改める）を、1つのアプリの中で、待たされない体験として提供し、データは自分のMacに残る。使い心地は価値の一部であり、機能を足すより軽さを守る。Reeder Classic 5.5.1の滑らかな3カラム、落ち着いたダーク表示、Vim風のキーボード操作を読書体験の基準とする。機能の追加や設計に迷ったときは、ビジョンの「迷ったときの問い」に照らす。

**ループ**: 読む（3カラム・キー操作）→ 書く（記事を見ながら、`n`で横に開いた1つのノートに、自分の言葉で書く）→ 理解する（自分の言葉のノートが残る）。AIが要るときは、システムのWriting Toolsを使うか、ノートをコピーして好きなAIへ貼り付ける。アプリは自前のAIを持たず、AIを使わなくてもすべての操作ができる。

V1は本人のMacで使う。Backend、アカウント、複数端末同期は持たない。新規ライブラリは空で開始し、プロトタイプからのデータ移行は対象外（[決定0001](decisions/0001-fresh-library-no-prototype-migration.md)）。

ベータ間のデータ互換は保証しない。同じ版での保存・再起動による保持は維持し、1.0以降は更新・モデル変更をまたぐ保持を保証する。ライブラリの初期化がエラーを返した場合は起動エラーを示し、自動削除・作り直しをしない。非互換DBのSwiftData上の挙動は未検証。ベータ配布時は互換性の制約をリリースノートに明記する（[決定0003](decisions/0003-beta-data-compatibility.md)）。

## 2. 製品の約束

- 滑らかな3カラムとキーボード操作を提供し、フォーカス・読書位置・日本語入力・システムのアクセシビリティを保つ。
- 取得できる本文を読みやすく表示し、取得できないときもRSS要約と原文リンクで読書を続けられる。全文完全性は保証せず、入力カバー範囲を示す。
- 既読は閲覧履歴、Starは「あとで咀嚼したい」の印、ノートは自分の言葉で書く1つの場所として区別する。ノートは、1つのMarkdownの文書だけを持つ。
- 保持期間内の記事内容と、ノートはオフラインで読める。本人が書いた内容は自動削除しない。
- アプリは自前のAIを持たない。ノートを書くときは、システムのWriting Toolsが使える（使えるかどうかはMacの設定による）。ノートは、ボタン1つで、そのままコピーして、どのAIへも貼り付けられる。AIが使えなくても、すべてできる。

## 3. V1の読書と理解

### 3.1 3カラムと読書操作

| カラム | 役割・表示 |
|---|---|
| 左 | Feeds（すべての記事・未読・Star）、購読元（フォルダ・購読元）の対象選択。購読元の横にサイトアイコン。購読元の区画は畳める。右上は右詰めで購読追加・更新の順。「購読元」の見出しの右端には、マウスを重ねたときだけ小さな＋が出て（左上の＋と同じオレンジ）、購読元の追加ができる（見出しは固定されるので、項目が多くても届く）。更新中は更新ボタンの矢印そのものが回り（Reduce Motionでは動かさない）、ボタンは押せるまま（更新中の再実行は何もしない）。Hide Sidebarとフォルダ整理ボタンは置かない。サイドバーは、元ページを開いたときとノートを開いたときに自動で畳まれる（決定0046・0049） |
| 中央 | 一覧の上に、題と件数を、ウインドウの上の帯（窓のボタンの行）の下に置く（Reederと同じ。題の1行目は、右の列の✕と同じ高さ。大きさは17pt。決定0048）。選んだ対象の記事一覧。記事は上段左に購読元、右に公開日時、下段にタイトル・要約・記事画像。見出しとFaviconで興味を判断するため、見出しを一番大きくし（14pt）、要約（11pt）と購読元・公開日時（10pt）は補足として小さくする。境界のドラッグで幅を広げられる。読む面（一覧・記事・ノート）は同じ1色の暗い面にそろえ、ツールバーやノートの上部に別の灰色の帯と線を置かない（サイドバーだけが少し明るい）。色は控えめにする: アクセントは落ち着いたオレンジ1色で、未読の小さな点、購読追加・更新ボタン、ノートのリストの記号にだけ使い（購読元の名前は色を付けず灰色）、選択行はシステムの青ではなく静かな灰色にする。記事の見出しは26pt・semiboldとする。新しい記事が更新で届いたとき、一覧が先頭にあれば、新しい記事が上から滑り込み、既存の行が下へ押し出される（動きは1回の更新で最大20件まで。Reduce Motionでは動かさない）。先頭にないときは、読んでいる記事の位置を動かさない。手動更新も、起動・復帰・30分ごとの自動更新も同じ動きである |
| 右 | 記事本文。ノートは、ツールバーのボタン（`⌥⌘I`）か`n`で、記事の右に開閉する1つのノート（第3.3節。幅は境界のドラッグで変えられ、次の起動でも保つ）。記事の上部ボタンはStar・外部ブラウザ（globe）。外観切替はSettingsのAppearance（システム／ライト／ダーク）に置く |

購読はOPMLファイルからもまとめて取り込める（ファイル ▸「OPMLを取り込む…」。ショートカットは付けない。購読は一度の保存ですぐ追加し、記事はあとから順に届く。フォルダは1階層で、深い階層は最上位のフォルダにまとめる。すでにある購読は追加も移動もしない。結果は短い文で示す。決定0041）。購読はRSS/Atom URLから追加する（`http://`のアドレスは`https://`で確認し、購読するのもそのURLにする（ポート番号つきは打ったまま。決定0040）。サイトのURLでもよい: ページが`<link rel="alternate" type="application/rss+xml">`などで示すフィードを探し、最初の1件を使う。見つけたフィードのURLを画面に示し、購読するのはそのフィードのURL。保存済みの購読の更新では行わない。決定0038）。追加の画面はURL欄と「キャンセル」「追加」だけにする。URLは入力中に確認する: 入力が止まって約0.8秒後（貼り付けはすぐ）に取得して読み、欄の下の1行に「確認中…」・「✓ フィード名」・失敗の理由のどれかを示す。「追加」は、フィードを読めたときだけ押せる（200であるだけでなく、RSS 1.0・RSS 2.0・Atomとして解析できたとき）。確認で取得したフィードをそのまま追加に使う。入力中は、ホストが完成して見えないURL（例: https://exa、https://example.c）は送らない（Returnを押したときは、localhostのような名前も使う）。すでに購読しているURLは「すでに購読しています」と示し、追加しない。失敗の理由は原因ごとの短い文で示す（404・読めない・サーバーのエラー・ネットワークなし・応答なし・サーバーが見つからない・安全な接続ができない・httpは使えない・大きすぎる・Webページでフィードではない・XMLの誤り）。XMLが禁じる制御文字だけが原因のときは、それを除いて読む。決定0036。追加先のフォルダは、フォルダ行にマウスを重ねたときの＋ならそのフォルダに決まる（画面の見出しに「「Tech」に購読を追加」のように示す）。「購読元」の見出しとツールバーの＋から開いたときは、フィードを読めた後に、フォルダの入力欄と候補（「フォルダへ移動…」と同じ部品）が現れる（フォルダが1つ以上あるときだけ）。何も選ばず貼り付けてReturnなら未分類に追加し（速い道を保つ）、名前を打てば最も近い候補が選ばれ、まだ無い名前は「作って追加」を選べる。決定0037。購読を移すと、行がなめらかに新しい場所へ動き、移した先のフォルダが開く（Reduce Motionでは動かさない）。購読は右クリックの「フォルダへ移動…」（入力欄つきの小さな選択画面。打つと既存のフォルダが絞り込まれ、まだ無い名前なら「作って移動」を選んで、入力と移動を同時にできる。↑↓・Return・Esc。「未分類」へも戻せる。フォルダは最初の購読を入れて作る）と、サイドバーでフォルダへのドラッグ&ドロップで移す。XMLの直接入力と合成サンプルは、⌥を押しながら追加を開いたときだけ出る障害確認用である。追加済み購読の右クリックで更新・名前の変更（行の中でその場で）・フォルダへ移動・解除を操作する。フォルダの名前変更と記事の集約を提供し、複数購読に属する同じ記事・未読件数を重複計上しない。空フォルダ・入れ子は持たず、最後の購読が外れるとフォルダ表示も消える。

一覧の公開日時は今日なら時刻、過去なら日付と時刻、現在の年以外なら年も示す。日時不明は「—」とし、受信日時で補わない。未読は購読元名の落ち着いたアクセント色（オレンジの印は付けない）と明るい文字、既読は行全体を落ち着いた灰色にする。長い購読元名は末尾を「…」で省く。選択中は読みやすいコントラストを保つ。

| キー | 操作 |
|---|---|
| `j` / `k` | 次／前記事 |
| `s` | Starの付け外し |
| `n` | ノートを開く／閉じる（ツールバーのボタン、`⌥⌘I`と同じ。編集できる欄に入力していないとき） |
| `m` | 既読／未読切替 |
| `b` | 元ページを既定の外部ブラウザで開く |
| `v` | 元ページをアプリ内で開く |
| `Esc` | 原文またはノートを閉じて、同じ記事の記憶した読書位置の元の画面へ戻る（日本語の変換中は、変換の取り消しが先。決定0050） |

原文中も`j/k/s/n`を使える。`j/k`または一覧クリックで別記事を選ぶと原文を閉じ、新しい記事の通常の読書表示に戻る（原文は、入ってきたときの逆に、右へすべり出ながら閉じ、その下に次の記事が現れる。入るときと同じ0.3秒。Reduce Motionでは動かさない。原文に覆われている間は、読書表示の縦の動きは付けない。決定0044・0046）。原文の上部の左の「×」（`Esc`と同じ）で閉じる。原文を開くと、左のサイドバーが畳まれ（ウィンドウの幅によらない。一覧は幅を保ったまま左端へ寄り、原文は記事の列とサイドバーを合わせた幅を使う）、閉じると、閉じ方によらず（`Esc`・「記事に戻る」・`j/k`・一覧クリック）サイドバーが戻る。畳む・戻す動きは、原文のすべりと同時に動く約0.3秒の1つの動きで、システムの標準の分割ビューの動きを使う。Reduce Motionでは動かさない（決定0046）。読み込み完了で本文領域の高さを変えない。Starやノートの開閉は現在の記事・読書位置を保つ。テキスト入力欄（ノートのエディタを含む）・IME変換・修飾キー付き操作では文字入力と標準操作を優先する。主要操作はキーボードだけでも完結する。外部ブラウザ内の操作は対象外。

次記事は下から上、前記事は上から下へ短く素早く入る。原文の開閉は、右から左へ入り右へ戻る短いスライド（本のページを進める向き）でつなぎ、Reduce Motionでは移動を無効にする。ノートを閉じると、元の画面（対象・選択記事・読書位置）に戻る。ノートは、パネルの開閉・幅を復元する。

本文またはRSS要約が記事ペインに実表示された時点で初回既読日時を記録する。一覧スクロール・本文取得だけでは既読にしない。再受信・再表示でも初回日時を更新しない。全文取得に失敗してもRSS要約と原文リンクを示し、paywall・ログイン・robots制限などを回避しない。

RSS提供内容と抽出本文のリンク・引用構造を保持し、リンクはクリックして既定ブラウザへ開ける。引用は本文と区別し、本文カバー範囲は末尾に一度だけ控えめに示す。書式情報のない保存本文はテキストとして読める。記事を開いたときは、フィードが提供した本文（なければRSS要約）をそのまま出し、元ページの取得も本文の差し替えもしない（RSS優先）。詳しくは「v」（アプリ内の原文）か「b」（ブラウザ）で見る。「全文を取得」（取得済みなら「本文を再取得」）を押したときだけ、原文のページから本文を抽出して出す。抽出は、短い断片が過半の（ページのメニューや数字ばかりの）結果を本文とせず、失敗時は今の本文を保って失敗を示す。要約をノートへ送るとき、フィード本文が1,000文字未満なら、AIの入力にだけ元ページの抽出本文を使う（保存も表示もしない。取れなければフィード本文）。

### 3.2 Star

**Star**は「あとで咀嚼したい」の印で、既読日時を変えない。現在の付与状態と付与日時を保存する。解除するとStar一覧から外れ、付け直すと新しい付与日時を使う。選択中の記事を解除しても次の移動までは表示と位置を保つ。本文が期限切れになっても、Star・タイトル・URLは保持する。Starはノートとは独立している。

### 3.3 ノートと保持・削除

**ノート**は、アプリに**1つだけ**の、Markdownのテキスト文書である（[決定0049](decisions/0049-one-note-and-no-ai-of-its-own.md)）。一覧・新規作成・名前・フォルダ・削除・削除の取り消しは無い。入力のたびに保存し（入力した文字を整えず、そのまま保存する。保存失敗を成功扱いにせず、IME変換中の入力を妨げない）、次の起動でも、続きから書ける。ゴール・タグ・フォルダ・検索・入れ子は持たない。

**開き方（記事を見ながら書く）。** 記事の一覧のある画面（Feeds・Star・購読元・フォルダ）で、`n`（編集できる欄に入力していないとき）、ツールバーのノートのボタン、`⌥⌘I`のどれかを押すと、`v`と同じ約0.3秒の動きで、サイドバーと一覧が左へ畳まれ、右からノートが入り、**左が記事、右がノート**になる。もう一度押すと、逆の動きで、元の画面（対象・選択記事・読書位置）に戻る。Reduce Motionでは動かさない。`n`は、ノートに何も書き込まない（要約・出典・見出しは入れない）。

**配置を替える。** ノートが開いている間は、ツールバーのノートのボタンの隣の「配置」ボタンで、2つの配置が入れ替わる。**記事の横**（左が記事、右がノート。一覧は畳まれている）と、**一覧も出す**（左から一覧・記事・ノート）である。ノートを閉じている間は押せない。ボタンは1つで、ほかの段階は持たない。配置を替えても、選んだ記事とスクロール位置、ノートの文は変わらない（決定0050）。

**別の記事へ移る・閉じる。** どちらの配置でも、フォーカスが記事か一覧にあるとき、`j`/`k`は次・前の記事へ移り、ノートは開いたままである（ノートのエディタにフォーカスがあるときは文字入力。記事を替えるにはパネルの上の矢印を使う）。`Esc`は、ノートを閉じて元の画面（同じ記事）に戻る（日本語の変換中は、変換の取り消しが先。決定0050）。ノートの左上（右の列の左上）の「×」（原文の「×」と同じ場所・同じ動き）でも閉じる。ノートのパネルの上の矢印（`⌥⌘↑`／`⌥⌘↓`）は、ノートを開いたまま、記事だけを次・前に替える。選んだ記事とスクロール位置は、ノートの開閉で変わらない。

**エディタ。** プレーンなMarkdownの文字を編集し、システムの文字サービス・元に戻す・日本語入力・Writing Tools（書き直し・校正・要約・要点・リスト・表など。システムがテキスト欄に出す。第5節）を使える。パネルの幅は境界のドラッグで変えられ（初めは640pt、広げられるのは1,280ptまで、最小は300pt。窓が狭いときは記事の最小幅360ptと、3列のときは一覧の最小幅280ptを残す。以前の版で保存した幅は、この版の最初の起動で一度だけ捨てる）、次の起動でも保ち、ドラッグでは畳めない。`#`で始まる行（見出し。`#`は1〜6個で、後ろに空白か行末）を太く大きく、`-` `*` `+` または番号（`1.` `1)`）で始まる行（リスト。行頭の空白は8個まで）を記号に色を付け、折り返した行を文字の位置に揃えて見せる。これは表示だけで、保存される文字は一切変わらず、Enterでリストを続けたり、引用符・ダッシュを置き換えたりしない。貼り付けとドロップはプレーンテキストだけを入れる。日本語の変換中は整形せず、確定か取り消しの後に整える。太字・斜体・コード・表・チェックリスト・プレビューはV1後。ノートの文章は、アプリのAIや他の操作が本人の操作なしに書き込まない。

**Markdownをコピー。** ノートのパネルのヘッダーに「Markdownをコピー」がある。本文を、そのまま（文字を整えず）コピーする。本文が空または空白だけのときは操作を無効にする。コピーしたものを、本人が、好きなAI（Claude・Codex・Geminiなど）へ貼り付ける。アプリは、ほかのアプリを起動せず、ファイルを作らず、通信しない。

記事本文・RSS要約は初期30日、Settingsで7 / 30 / 90 / 365日から選ぶ。未読は初回受信、既読は初回既読を起算点とし、再受信・再表示で期限を延長しない。短縮時・本文一括削除時は対象を確認する。期限切れ本文・要約は自動削除し、削除状態と原文リンクを残す。

ノートの全文は、記事の期限切れ・本文削除・購読解除でも保持する。ノートの文章を消すのは、本人が文字を消すときだけである（ノートそのものを削除する機能は無い）。

### 3.4 Faviconとサムネイル

購読元のFaviconと記事画像を区別する。RSS/Atomが提供する記事画像を優先し、はてなブックマークでは記事画像メタデータを使う。中央と右の読書表示に利用可能な画像を示す。画像なし・取得失敗・オフラインでも読書を止めず、非同期画像の到着で行高・選択・スクロール位置を変えない。再利用用のキャッシュを持つが、ノートの保存契約には含めない。

## 4. 製品判断の軸

読書の連続性、開いたことと関心の区別、本人が選ぶ記録、入力範囲の正直な表示を優先する。取得成功率を上げるために制限を回避したり、欠けた本文を推測で補ったりしない。個人の読書履歴をサーバーへ預けることを前提にせず、AIの提案も本人が確認して自分の言葉にする。

## 5. AIの使い方

V1のアプリは、**自前のAI機能を持たない**（[決定0049](decisions/0049-one-note-and-no-ai-of-its-own.md)）。AIによる要約・提案・ノートへの書き込み・外部サービスへの送信はしない。アプリが自動で通信することも、AIのために起こさない。

### 5.1 ノートを書くとき: システムのWriting Tools

ノートのエディタは、macOSの標準のテキスト欄なので、**Writing Tools**（校正・書き直し・口調の変更・要約・要点・リスト・表・Composeなど）を、システムが出す（Apple Intelligenceが使えるMacで、選んだ文字の右クリックなどから）。これは、本人が文字を選んで操作したときだけ働く、システムの機能である。アプリは何も足さず、結果の質も保証しない。使えない設定のMacでも、ノートの作成・編集・コピーのすべてができる。記事の文章を要約したいときは、本人が文字を選んでノートに貼り付け、Writing Toolsを使う。

### 5.2 ノートを他のAIへ渡す: Markdownをコピー

ノートのパネルのヘッダーの「Markdownをコピー」は、本文を、システムのペーストボードへ、そのまま（UTF-8の文字、末尾も変えない）コピーする。本人が、Claude・Codex・Geminiなど、好きなAIへ貼り付けて渡す。アプリは、AIを起動せず、ファイルを作らず、通信せず、確認画面も持たない。端末の外へ出るのは、本人が貼り付けたときだけである。本文が空または空白だけのときは、操作を無効にする。

## 6. 制約と対象外

- macOS 27.0以降（サポート下限。CIのビルド下限は26.6のまま。[決定0007](decisions/0007-support-floor-macos-27.md)）。Backend、アカウント、同期、サーバー側巡回・AI処理、共有ノート、push通知はV1の対象外。
- 入れ子／空フォルダ、複数のノート、ノートのフォルダ・階層・タグ・検索・ゴール、時間軸（日次・週）のノート、システムの共有サービス（メッセージ・メールなど）はV1の必須範囲外。旧プロトタイプのLikeとその互換・移行は対象外で、Starは別の新しい関心の印。
- paywall、購読制、ログイン、captcha、robots制限の回避、全文完全性の保証は行わない。
- アプリ自前のAI機能（要約・下書き支援など。必要になれば、新しい決定記録で）、アプリ内BYOK/API生成、端末外のAI（Private Cloud Computeなど）、特定のAIアプリへの専用連携（Markdownをコピーだけを置く）、AIの自動送信・記録・事実性保証は対象外。
- アプリ内の表示言語・タイムゾーン設定は対象外。
- ソースはApache-2.0。LICENSEと必要な第三者ライセンス・著作権表示・NOTICEを同梱し、記事・feed・商標・サービス規約にはUnagi Readerのライセンスを適用しない。
- 公開対象はコード・仕様・合成サンプル／テストだけ。本人の購読・履歴・取得記事・ノート・認証情報を含めず、公開前に差分と履歴を確認する。ソース公開は製品受入後の別判断。App Store公開・署名配布はV1の受入条件ではなく、方針の承認を公開・配布操作の許可とは扱わない。
- エージェント開発の境界と検証は[Architecture §4](architecture.md#4-aiエージェントによる開発)に定める。指示文だけでOSの隔離が成立したとは扱わない。

### 7.1 1.0の出荷条件

- 保存スキーマを`VersionedSchema`として固定する。
- 1.0リリースタグを起点とする合成ストアの保持検証をCIへ必須で組み込む。購読・記事・既読・Star・ノートを新版で開き、再openして保持を確認する。未実行・スキップを成功扱いにせず、以後のモデル変更でも継続する。
- Bundle ID、保存先、署名・sandbox構成を確定して保存・再起動・更新を検証する。ベータDBを開けるか確認し、開けない場合の退避案内を用意する。
- 配布物のversion・build番号・署名・案内・ZIP・hashの作成を再現可能にし、CIのad hoc開発ビルドとの違いを示す。

## 8. V1後の候補

本人の不便が確認された場合だけ検討する。完了条件・実装の約束ではない。

- ノートへの挿入として、HIGに沿って作り直す端末内の要約（採用する場合は新しい決定記録で扱う）、端末外のAI（BYOKなど）による下書き支援、表示言語／タイムゾーン設定。
- ノートの見た目の整形の拡張（表・チェックリスト・プレビュー）、複数のノート・ノートのフォルダ・検索・タグ、ノートの一部だけを渡す操作、システムの共有サービス、時間軸の振り返りビュー、URLコピー。

Backend・同期は必要性が生じた時点で製品判断からやり直す。
