# Feeeder 製品要求仕様書（PRD）

更新日: 2026-10-05

状態: 実装開始承認済み。未決事項4件の製品判断は2026-10-04に合意済み。新規ライブラリ開始を含む改訂PRD全体と実装計画は、2026-10-05に利用者がPdMとして承認した。完成後の実機デモによるV1製品受入は未完了。技術候補とエージェント実行ハーネスは [Architecture](architecture.md) を参照する。

## 1. 目的と対象利用者

Feeederは、長年RSSを使い、読書体験を大切にする技術に詳しい熟練ユーザーのための、macOS向けプライベートRSSリーダーである。対象ユーザーはReeder Classic 5.5.1の滑らかな3カラム、落ち着いたダーク表示、Vim風のキーボード操作を愛用している。多くの記事を素早く読み分け、気になった考えを後から自分の言葉で振り返りたい。

**友人への一言:** 「Reederのように気持ちよくRSSを読んで、開いた記事から『今週、自分は何を追っていたか』をノートにできるMacアプリです。必要なときだけAIに相談し、最後は自分の言葉で残せます。」

V1は本人のMacで使う製品で、Backend API、アカウント、複数端末同期を持たない。ソースコードはApache-2.0を前提とする。ライセンスはRSS記事など第三者コンテンツの権利を与えるものではない。

V1は新しい空のライブラリから開始する。2026-10-05に利用者が引き継ぐデータはないと確認したため、プロトタイプからのデータ移行は対象外とする。

## 2. 製品の約束

- macOSらしい滑らかな操作と慣れた読書習慣を保つ。左から購読リスト、記事一覧、記事本文の3カラムで、ダーク表示とシステム外観への追従を提供する。キーボード、フォーカス、スクロール、原文閲覧からの復帰が自然につながり、日本語入力を妨げない。システムのアクセシビリティ設定と標準的なMac操作に沿う。
- RSS/Atomの購読先を登録し、フォルダと未読件数で見つけやすく整理する。記事一覧では`j/k`で記事を移動し、`b`で元記事を外部ブラウザに、`v`でアプリ内に開き、`Esc`で読書位置へ戻れる。
- 一覧をスクロールしただけでは既読にしない。キーボード移動を含め、本文またはRSS要約を記事ペインに表示した時点で既読にする。
- 全文が得られない記事も読書の流れを止めない。RSS要約を表示し、本文カバー範囲を控えめに示し、原文リンクを残す。
- 読んだ記事を週ごとの自分の記録にまとめられる。ノートは複数作成・編集でき、AIを使わずに保持できる。保持期間内の記事本文・RSS要約と保存済みノートは通信がないときも読める。記事本文の期限切れや購読解除でもノートと出典タイトル・リンクは残り、ノートを自動削除しない。
- 外部AIへ渡す対象と内容は利用者が選び、確認する。AIの返答も利用者がレビューして自分のノートへ反映する。

## 3. V1の読書と振り返り

V1の読書では、購読元の記事・メタデータを扱い、利用者が開いた記事の内容を記事ペインに表示する。本文取得が成功すれば読みやすい本文を表示し、全文が得られなければRSS要約を表示する。どちらの場合も記事ペインに内容が初めて表示された時点で既読となり、その日時を記録する。再表示では既読日時を変えない。リストだけの走査は未読状態を保つ。ネットワーク障害や本文不足で読書が遮られず、paywallやログイン制限を回避する取得は行わない。

振り返り・記録は月曜から日曜までの暦週を基本とする。初期の対象期間上限は7日で、最後に終了した週を先に開き、現在週は下書きとして扱う。その週に初めて既読になった記事を候補とし、受信しただけの記事は含めない。週が終わってもノートは編集できる。週ごとに既定のノートを一つ持ち、同じ週にサイト別・トピック別などの追加ノートを作れる。各ノートは編集可能で、出典リンクを保持する。

その週の初回ノート作成時に、Macの現在のタイムゾーンで週の範囲を決め、期間とタイムゾーンを保存する。現在週の下書きも同じ扱いとする。作成済みの週は保存した範囲で候補記事を集計し、期間をタイムゾーンとともに表示する。Macのタイムゾーン変更だけでは、作成済みの週の範囲・期間表示・候補記事の集計範囲を変更しない。同じ週に追加するノートは、その週に保存した期間とタイムゾーンを引き継ぐ。ノートの本文・採用済みの出典と、既読になった日時そのものも自動変更しない。V1にはアプリ内でタイムゾーンを変更する設定を設けない。

Dogfoodingでは、タイムゾーン変更前後の週の選択と、現在週の下書きで期間を固定する使い勝手を確認する。

記事本文とRSS要約の保持期間は初期値30日（約1ヶ月）とし、Settingsで変更できる。未読記事は初回受信時、既読記事は初回既読時を起算点とする。再受信や再表示だけでは期限を延長せず、既読日時も更新しない。Settingsには保持期間と削除対象を示し、ノートが自動削除の対象外であることを明示する。保持期間を短くする際は、削除対象を確認してから適用できるようにする。

期限を過ぎた記事本文・RSS要約は自動削除する。ノートへの採用は記事全文の無期限保存を意味しない。記事の期限切れ・手動削除・購読解除でも、ノート本文と採用済み出典のタイトル・URLは保持する。ノートは本人が明示的に削除し、削除前に確認する。記事本文・RSS要約の一括削除も提供し、対象を確認できるようにする。本文が削除済みの記事はその状態を示して原文リンクを残す。オフライン閲覧とAIハンドオフに利用できる記事内容は、その時点で保持している本文・RSS要約に限る。

Dogfoodingでは、30日の保持期間で週の振り返りに十分な余裕があるかと、実際の保存容量を確認する。

## 4. 製品判断の軸

- 読む行為そのものを関心の記録にする。別のLike操作を求めず、週ノートに含める記事は利用者が選ぶ。
- まずMac上の読書と記録を完成させる。個人の購読・閲覧履歴をサーバーへ預けることを製品価値の前提にしない。
- 本文取得の成功率より読書の連続性と入力範囲の正直な表示を優先する。得られない本文を推測で補わない。
- AIは本人の思考を補助する。出典を確認して外部AIへ渡すか、AIを使わず自分で書くかを常に選べる。
- 振り返りは週単位を出発点にする。長い期間を一度に要約するより、毎週の記録を積み重ねる。

## 5. AIハンドオフと内容の確認

週の振り返りと記事単位の要約依頼の両方で、利用者が選んだ出力言語と出典を含むレビュー可能なプロンプト／ソースパッケージを作る。利用者はソースを個別に除外できる。V1の連携先はClaude Desktopに限定する。パッケージを確認して「Claudeで開く」を操作すると、Feeederがファイルを生成し、Claude Desktopを直接起動して依頼文と生成ファイルを送信前の入力欄へ渡す。利用者がClaude側で内容と添付を確認して送信する。毎回ファイルを探して手動添付することを通常経路にしない。アプリは自動送信せず、返答をノートへ自動書込みしない。

直接起動・依頼文の事前入力・ファイル添付は、対応するClaude Desktop環境で実際に動作を確認した経路を採用する。利用不可や起動失敗の場合は状況を示し、確認済みパッケージを保って再試行・コピー・ファイル書き出しができるようにする。コピーや書き出しだけでは、直接起動と添付を含むV1の受入条件を満たしたことにしない。

パッケージは本文が取得できたかRSS要約だけかを正確に示し、含めた出典を追跡できるようにする。AIへの依頼文には、与えられた内容にない事実を作らないよう求める。ただし返答の真実性は保証しない。利用者が返答を読んで採否を決め、必要に応じて自分で編集する。

選択したソースを送信経路の長さ制約だけを理由に黙って省略しない。記事本文・RSS要約はファイルへ含め、起動リンクの文字数制約で本文を切り詰めない。添付の制限に収まらない場合は制約を示し、内容を保持した分割などの別の受け渡し方法を利用者が確認して選べるようにする。具体的な転送上限と経路の技術設計はArchitectureで扱う。

## 6. 制約と対象外

- macOS 26.6以降を対象とするネイティブmacOSアプリ。プライベート利用を前提とし、FeeederのソースはApache-2.0とする。
- V1ではRSS/Atomが購読記事とメタデータの基準。Backend、アカウント、複数端末同期、サーバー側巡回・AI処理、共有ノート、push通知は対象外。
- Likeボタン・Like状態・Like期間は対象外。
- paywall、購読制、ログイン、captcha、robots制限を回避する取得は対象外。全文完全性は保証しない。
- V1のアプリ内BYOK/API生成は対象外。
- ChatGPTなどClaude Desktop以外への専用AI連携はV1の対象外。
- アプリ内で表示言語・タイムゾーンを変更する設定はV1の対象外。AI依頼時の出力言語選択はV1に含む。
- AIによる自動送信、自動記録、事実性保証は対象外。
- App Store公開と署名配布はV1の製品受入条件ではない。Apache-2.0でのGitHub公開は製品受入後の別の公開判断とする。
- ソース公開の対象はFeeederのコード・仕様・合成サンプル／テストデータとする。本人の購読情報・閲覧履歴・取得記事・ノート・認証情報をリポジトリに含めない。公開前に対象の差分と履歴を確認する。公開方針の確定を、GitHubへの公開操作や署名配布の指示とは扱わない。
- FeeederのコードにはApache-2.0のLICENSEを同梱する。第三者コードを追加する際は各ライセンスに従い、ライセンス・著作権表示・必要なNOTICEを公開対象に含める。RSS記事など第三者コンテンツにFeeederのライセンスを適用しない。
- エージェント実行の工学受入依存は [Architecture](architecture.md) に定める。現時点でハーネスが稼働済みとはみなさない。

## 7. 観察可能なV1受入シナリオ

| ID | 利用者シナリオ | 合格条件 |
|---|---|---|
| PRD-01 | 熟練RSSユーザーが購読を整理して記事を読む | 購読リスト・記事一覧・本文の3カラム、ダーク表示とシステム外観追従、RSS/Atom購読のフォルダと未読件数がある。`j/k`で記事移動、`b`で外部ブラウザ、`v`でアプリ内表示、`Esc`で読書位置へ復帰できる。連続操作でも目立つ停止・本文の取り違え・意図しないスクロール飛びがなく、日本語入力を妨げない。キーボードだけでも主要操作が完結し、VoiceOverなどシステムのアクセシビリティ設定を妨げない。PdMがReeder Classicと実機で比較して読書の滑らかさを確認する |
| PRD-02 | 未読一覧を走査して記事を開く | 一覧のスクロールだけでは未読を保つ。クリックや`j/k`で記事ペインに本文またはRSS要約が表示された時点で既読になる |
| PRD-03 | 全文取得に失敗した記事を読む | 読書を遮るプロンプトや回避取得なしにRSS要約、控えめな本文カバー範囲表示、原文リンクが示される |
| PRD-04 | 前週を振り返り、ノートを編集する | 最後に終了した週が先に開き、現在週は下書き。初期は月曜から日曜の暦週・最大7日。その週の初回ノート作成時に期間とタイムゾーンを保存し、現在週の下書きも固定する。Macのタイムゾーン変更後も保存済みの期間・タイムゾーンを表示して同じ範囲で候補記事を集計し、既読日時とノートの本文・出典は変えない。同じ週の追加ノートは保存済みの期間・タイムゾーンを引き継ぐ。既定ノートに加え任意の複数ノートを作成でき、各ノートをAIなしで編集し、再起動・オフライン・購読解除後もノートと出典リンクを読める |
| PRD-05 | 週または記事についてClaude Desktopへ依頼する | 出力言語を選び、ソースを含める／除外し、パッケージと入力カバー範囲を確認して「Claudeで開く」を操作できる。対応環境でClaude Desktopが未起動でも直接起動し、依頼文が事前入力され、選択ソースを含む生成ファイルが添付された状態になる。利用者がClaude側で送信する。選択ソースの無言の省略、自動送信、自動書込みがない。添付制限時は内容を保つ別経路を提示し、起動失敗時もパッケージを失わず再試行・コピー・書き出しできる。コピーや手動添付だけを通常経路として合格にしない |
| PRD-06 | AIの返答を記録する | 返答の事実性をアプリが保証せず、利用者が内容を確認してから自分のノートへ採用・編集できる |
| PRD-07 | 最終デモをレビューする | PdM／本人が本表のV1シナリオと製品範囲を実演で確認し、明示的に承認する。承認前は製品受入としない |
| PRD-08 | 記事の保持期間を設定し、保存データを整理する | 記事本文・RSS要約の初期保持期間は30日で、Settingsから変更できる。保持期間と削除対象、ノートが自動削除対象外であることが示される。期限切れ・記事本文の一括削除・購読解除後もノート本文と出典タイトル・URLが残る。保持期間短縮と手動削除では対象を確認でき、ノート削除は本人の明示操作と確認で行う。期限切れ本文をオフラインで読める、またはAI入力に含められると誤認させない |

## 8. V1後に検討する候補

以下はV1の完了条件でも実装の約束でもない。V1を使った本人の不便が確認できた場合にだけ、製品哲学との整合を判断する。

- 外部AIへの受け渡しが繰り返し負担になる場合、アプリ内のBYOKによる下書き支援を検討する。本人によるソース選択、送信前確認、編集可能なノートは維持する。
- アプリ内で表示言語（Language）と振り返りのタイムゾーン（Timezone）を変更できる設定を検討する。
- Claude Desktop以外の連携先が必要になった場合、同等の直接起動・添付体験を提供できるかを確認してChatGPTなどへの対応を検討する。

Backend、複数端末同期、独立したLikeの復活は、この候補一覧には入れない。必要性が生じたときに製品判断からやり直す。
