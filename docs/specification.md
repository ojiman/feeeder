# Feeeder 製品要求仕様書（PRD）

更新日: 2026-10-09

本書はV1の現行製品要件を定める。Dogfooding改訂仕様は[PR #6](https://github.com/ojiman/feeeder/pull/6)、実装計画は[PR #7](https://github.com/ojiman/feeeder/pull/7)でPdM承認済み。以後の変更は対象PRの明示的な承認またはマージで承認する。**仕様・計画の承認と、実機での最終製品受入は別であり、後者は未完了。**

技術設計は[Architecture](architecture.md)、決定の理由は[決定記録](decisions/README.md)、実測と未確認事項は[検証記録](verification/2026-10-07-feed-polish.md)を参照する。過去の実装計画・検証結果を現行の仕様や合格証拠として流用しない。

## 1. 目的と対象利用者

長年RSSを使う熟練ユーザーが、Macで多くの記事を気持ちよく読み分け、気になった考えを残して「今週、自分は何を追っていたか」を自分の言葉で振り返るためのリーダー。Reeder Classic 5.5.1の滑らかな3カラム、落ち着いたダーク表示、Vim風のキーボード操作を読書体験の基準とする。AIは必要なときだけ使える。

V1は本人のMacで使う。Backend、アカウント、複数端末同期は持たない。新規ライブラリは空で開始し、プロトタイプからのデータ移行は対象外（[決定0001](decisions/0001-fresh-library-no-prototype-migration.md)）。

ベータ間のデータ互換は保証しない。同じ版での保存・再起動による保持は維持し、1.0以降は更新・モデル変更をまたぐ保持を保証する。ライブラリの初期化がエラーを返した場合は起動エラーを示し、自動削除・作り直しをしない。非互換DBのSwiftData上の挙動は未検証。ベータ配布時は互換性の制約をリリースノートに明記する（[決定0003](decisions/0003-beta-data-compatibility.md)）。

## 2. 製品の約束

- 滑らかな3カラムとキーボード操作を提供し、フォーカス・読書位置・日本語入力・システムのアクセシビリティを保つ。
- 取得できる本文を読みやすく表示し、取得できないときもRSS要約と原文リンクで読書を続けられる。全文完全性は保証せず、入力カバー範囲を示す。
- 既読は閲覧履歴、Starは関心の印、スクラップは本人が残す記録として区別する。日次の記録を週の振り返りへつなぐ。
- 保持期間内の記事内容と保存済みノートはオフラインで読める。ノートと明示保存した出典・要約は自動削除しない。
- AIへ渡す内容と返答の採用は本人が決める。AIを使わずに記録を作成・編集できる。

## 3. V1の読書と振り返り

### 3.1 3カラムと読書操作

| カラム | 役割・表示 |
|---|---|
| 左 | Feeds（すべての記事・未読・Star・フォルダ・購読元）とNotes（日次ノート・週の振り返り）の対象選択。購読元の横にサイトアイコン。右上は右詰めで購読追加・更新の順。Hide Sidebarとフォルダ整理ボタンは置かない |
| 中央 | 選んだ対象の記事／ノート一覧。記事は上段左に購読元、右に公開日時、下段にタイトル・要約・記事画像。境界のドラッグで幅を広げられる |
| 右 | 記事本文／ノート編集。記事の上部ボタンはStarと外部ブラウザ（globe）だけ。AIの入口は日次・週ノート、外観切替はSettingsのAppearance（システム／ライト／ダーク）に置く |

購読はRSS/Atom URLから追加する。追加時に未分類・既存の1階層フォルダを選ぶか、新しいフォルダ名を入力する。追加済み購読の右クリックで名前・フォルダ・移動・解除を操作する。フォルダの名前変更と記事の集約を提供し、複数購読に属する同じ記事・未読件数を重複計上しない。空フォルダ・入れ子は持たず、最後の購読が外れるとフォルダ表示も消える。

一覧の公開日時は今日なら時刻、過去なら日付と時刻、現在の年以外なら年も示す。日時不明は「—」とし、受信日時で補わない。未読はオレンジの印と明るい文字、既読は行全体を落ち着いた色にする。選択中は読みやすいコントラストを保つ。

| キー | 操作 |
|---|---|
| `j` / `k` | 次／前記事 |
| `s` | Starの付け外し |
| `n` | 当日の既定ノートへスクラップ |
| `m` | 既読／未読切替 |
| `b` | 元ページを既定の外部ブラウザで開く |
| `v` | 元ページをアプリ内で開く |
| `Esc` | 原文から同じ記事の記憶した読書位置へ戻る |

原文中も`j/k/s/n`を使える。`j/k`または一覧クリックで別記事を選ぶと原文を閉じ、新しい記事の通常の読書表示に戻る。原文の開閉は右カラム内で行い、左・中央の幅と購読追加・更新ボタンを維持する。読み込み完了で本文領域の高さを変えない。Star・スクラップは現在の記事・読書位置を保ち、結果を示す。テキスト入力欄・IME変換・修飾キー付き操作では文字入力と標準操作を優先する。主要操作はキーボードだけでも完結する。外部ブラウザ内の操作は対象外。

次記事は下から上、前記事は上から下へ短く素早く入る。原文開閉も上下の短いスライドでつなぎ、Reduce Motionでは移動を無効にする。Notes往復でも同じ3カラムを保ち、Feedsへ戻ると対象・選択記事・読書位置を復元する。日次は当日、週は最後に終了した週を先に示す。

本文またはRSS要約が記事ペインに実表示された時点で初回既読日時を記録する。一覧スクロール・本文取得だけでは既読にしない。再受信・再表示でも初回日時を更新しない。全文取得に失敗してもRSS要約と原文リンクを示し、paywall・ログイン・robots制限などを回避しない。

RSS提供内容と抽出本文のリンク・引用構造を保持し、リンクはクリックして既定ブラウザへ開ける。引用は本文と区別し、本文カバー範囲は末尾に一度だけ控えめに示す。書式情報のない保存本文はテキストとして読める。「本文を再取得」で更新でき、失敗時は保存済み本文を保って失敗を示す。

### 3.2 Starと日次スクラップ

Starは現在の付与状態と付与日時を保存する。解除するとStar一覧・未採用の週候補から外れ、付け直すと新しい付与日時を使う。選択中の記事を解除しても次の移動までは表示と位置を保つ。解除・本文期限切れで保存済みノートを変更せず、期限後もStar・タイトル・URLを保持する。Starを付けずにスクラップできる。

スクラップは**タイトル・原文URL・保存時点で保持しているRSS要約・編集可能な本人のメモ**を保存する。抽出全文を複製せず、要約がない場合はタイトル・URLだけにして欠如を示す。同じ記事を同じ日次ノートへ再保存しても重複・内容やメモの上書きをしない。保存失敗は成功扱いにせず再試行できる。

日次ノートは初回作成時のMacの暦日の開始・終了・タイムゾーンを固定する。現在時刻を含む保存済みノートを優先し、なければ現在の暦日で作成する。タイムゾーン変更だけで過去の所属・内容を移動しない。日付をまたぐ最初のスクラップは新しい当日ノートへ入る。V1の保存先は当日の既定ノートだけとし、過去ノートは閲覧・編集できる。

### 3.3 週の振り返りと保持・削除

月曜から日曜までの暦週・最大7日を対象とし、最後に終了した週を先に開く。現在週は下書き。初回ノート作成時のMacのタイムゾーンで開始・終了・タイムゾーンを保存し、下書きも固定する。同じ週の追加ノートは保存した範囲を引き継ぐ。Macのタイムゾーン変更だけで期間表示・候補集計範囲・既読日時・本文・採用済み出典を変更しない。

初期候補は、その週に付与した現在Star付きの記事と、その週に保存した日次スクラップ。記事IDで重複をまとめ、複数スクラップがあれば当該週の最初の保存を初期選択にし、本人が別の保存内容も選べる。同じ週の初回既読履歴も別表示で確認できる。受信だけの記事は含めない。過去に読んだ記事へ今週Starを付けた場合は今週の関心とする。

週ごとに既定ノートと任意の追加ノートを作れ、週が終わっても編集できる。日次スクラップの採用時にタイトル・URL・保存済みRSS要約を出典として独立保存し、元の日次ノートの編集・削除には連鎖しない。日次本文・本人のメモは自動転記せず、本人がまとめる。

記事本文・RSS要約は初期30日、Settingsで7 / 30 / 90 / 365日から選ぶ。未読は初回受信、既読は初回既読を起算点とし、再受信・再表示で期限を延長しない。短縮時・本文一括削除時は対象を確認する。期限切れ本文・要約は自動削除し、削除状態と原文リンクを残す。

ノート本文・出典タイトル／URL・明示保存したRSS要約は記事の期限切れ・本文削除・購読解除でも保持する。ノートの削除は本人の明示操作と確認による。Star・採用は元記事全文の期限を延長せず、期限切れ全文をオフライン閲覧やAI入力に復活させない。ノートの保存済み要約は別の所有データとして利用できる。

### 3.4 Faviconとサムネイル

購読元のFaviconと記事画像を区別する。RSS/Atomが提供する記事画像を優先し、はてなブックマークでは記事画像メタデータを使う。中央と右の読書表示に利用可能な画像を示す。画像なし・取得失敗・オフラインでも読書を止めず、非同期画像の到着で行高・選択・スクロール位置を変えない。再利用用のキャッシュを持つが、ノートの永久保存契約には含めない。

## 4. 製品判断の軸

読書の連続性、開いたことと関心の区別、本人が選ぶ記録、入力範囲の正直な表示を優先する。取得成功率を上げるために制限を回避したり、欠けた本文を推測で補ったりしない。個人の読書履歴をサーバーへ預けることを前提にせず、AIの返答も本人が確認して自分の言葉へ編集する。

## 5. AIハンドオフと内容の確認

日次・週ノートから出力言語と出典を選び、ソースを個別に含める／除外する。一つの出典なら記事単位の依頼もできる。保存済みスクラップ要約と現在保持する記事内容を区別し、保存日時・カバー範囲・出典URLを確認できる。実際に含めた出典だけを示し、要約のみ・一部抽出を全文と誤認させない。依頼文は与えた内容にない事実を作らないよう求めるが、返答の真実性は保証しない。

利用者が省略のないパッケージを確認して「Claudeで開く」を操作すると、生成TXTと短い依頼文をClaude Desktopの送信前の入力欄へ渡す。V1の連携先はClaude Desktopのみで、現在の経路はCowork。本人がAttachを許可して内容を確認・送信し、必要なフォルダ許可も本人が判断する。毎回ファイルを探す手動添付を通常経路にせず、アプリは自動送信・返答の自動書込みをしない。

起動失敗・利用不可・取消時は確認済み内容を保ち、再試行・全文コピー・TXT書き出しへ戻れる。長さ制約だけを理由に本文・出典を黙って省略しない。添付制限時は内容を保つ分割などの別経路と制約を示し、利用者が選べる。コピーや書き出しだけで直接起動・添付の受入条件を満たしたことにしない。

記事由来のAI入力はその時点で保持する内容に限る。ノート所有の保存済み要約は元記事の期限後も使えるが、期限切れ全文は補完しない。アプリ管理コピーの期限・削除と、検証済みClaude環境は[Architecture §3](architecture.md#3-aiハンドオフ)に定める。本人の書き出し先とClaude側に渡った内容は、アプリの自動削除対象外。

## 6. 制約と対象外

- macOS 26.6以降。Backend、アカウント、同期、サーバー側巡回・AI処理、共有ノート、push通知はV1の対象外。
- 入れ子／空フォルダ、任意期間・任意ノートへのスクラップ、Starからノートへの新しい導線、URLコピー／標準ShareはV1の必須範囲外。
- paywall、購読制、ログイン、captcha、robots制限の回避、全文完全性の保証は行わない。
- アプリ内BYOK/API生成、Claude Desktop以外への専用連携、AIの自動送信・記録・事実性保証は対象外。
- アプリ内の表示言語・タイムゾーン設定は対象外。AI依頼の出力言語選択は含む。
- ソースはApache-2.0。LICENSEと必要な第三者ライセンス・著作権表示・NOTICEを同梱し、記事・feed・商標・サービス規約にはFeeederのライセンスを適用しない。
- 公開対象はコード・仕様・合成サンプル／テストだけ。本人の購読・履歴・取得記事・ノート・認証情報を含めず、公開前に差分と履歴を確認する。ソース公開は製品受入後の別判断。App Store公開・署名配布はV1の受入条件ではなく、方針の承認を公開・配布操作の許可とは扱わない。
- エージェント開発の境界と検証は[Architecture §4](architecture.md#4-aiエージェントによる開発)に定める。指示文だけでOSの隔離が成立したとは扱わない。

## 7. 観察可能なV1受入シナリオ

以下は合格条件であり、実行済み・合格済みの一覧ではない。仕様の詳細は第3・5節と合わせて確認する。

| ID | 利用者シナリオ | 合格条件 |
|---|---|---|
| PRD-01 | 購読を整理し、滑らかに読む | 3カラム・外観・フォルダ／未読件数・キー操作・Notes往復が第3.1節どおり動く。本文取り違え・目立つ停止・スクロール飛びがなく、入力／IME・VoiceOver等を妨げない。PdMがReeder Classicと実機比較する |
| PRD-02 | 未読一覧から記事を開く | 一覧スクロールでは未読。本文／RSS要約の実表示で初回既読日時を記録する |
| PRD-03 | 全文取得に失敗した記事を読む | 読書を遮らず要約・カバー範囲・原文リンクを示し、制限を回避しない |
| PRD-04 | 前週を振り返る | 第3.3節の期間固定・候補・複数ノート・出典採用が成立し、タイムゾーン変更後も固定範囲を使う。AIなしで編集でき、再起動・オフライン・購読解除後も記録を読める |
| PRD-05 | Claude Desktopへ依頼する | 第5節どおりレビュー後に未起動／起動済みClaudeへ依頼文と選択内容を渡し、本人のAttach後に添付状態となる。本人が送信する。省略・自動送信がなく、失敗時も再試行・コピー・書き出しへ戻れる |
| PRD-06 | AIの返答を記録する | 事実性をアプリが保証せず、本人が確認してノートへ採用・編集する |
| PRD-07 | 最終デモをレビューする | PdM／本人が本表と製品範囲を実演確認し、明示的に承認する。それまでは製品受入としない |
| PRD-08 | 保持・削除を設定する | 第3.3節の期限・確認・ノート非自動削除が成立する。期限切れ本文を読める／AI入力に使えると誤認させない |
| PRD-09 | Starを読み返す | キーとボタンが同じ状態を変更し、Star一覧を移動できる。付与日時で週候補へ現れ、解除後も記録、再起動・本文期限後もStar／タイトル／URLを保つ |
| PRD-10 | 読書中にスクラップする | 通常／原文表示から当日へ保存し、選択・位置を保つ。同日再保存で重複・上書きせず、翌日は新規ノート。期限・購読解除・再起動後も記録を保ち、保存失敗は再試行できる |
| PRD-11 | 多くの記事を読み分ける | フォルダ操作・重複しない集約・購読アイコン／記事画像が成立し、画像到着・失敗・オフラインで行高・選択・位置を変えない |

### 7.1 1.0の出荷条件

- 保存スキーマを`VersionedSchema`として固定する。
- 1.0リリースタグを起点とする合成ストアの保持検証をCIへ必須で組み込む。購読・記事・既読・ノート・出典を新版で開き、再openして保持を確認する。未実行・スキップを成功扱いにせず、以後のモデル変更でも継続する。
- Bundle ID、保存先、署名・sandbox構成を確定して保存・再起動・更新を検証する。ベータDBを開けるか確認し、開けない場合の退避案内を用意する。
- 配布物のversion・build番号・署名・案内・ZIP・hashの作成を再現可能にし、CIのad hoc開発ビルドとの違いを示す。

## 8. V1後の候補

本人の不便が確認された場合だけ検討する。完了条件・実装の約束ではない。

- BYOKによる下書き支援、表示言語／タイムゾーン設定、Claude以外の同等の直接起動・添付連携。
- 任意の日付・期間・ノートへのスクラップ、URLコピー／macOS標準Share。

Backend・同期は必要性が生じた時点で製品判断からやり直す。
