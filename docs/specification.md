## 1. 目的と対象利用者

**提供価値と対象利用者**は[ビジョン](vision.md)（英語。オーナーの言葉）に固定してある。要約: 量産される記事の中から本当に重要な記事を見つけ、自分の価値に変える。対象は2026年のITエンジニア。読む・メモする・AIに相談する・理解するのループを、1つのアプリの中で、待たされない体験として提供し、データは自分のMacに残る。使い心地は価値の一部であり、機能を足すより軽さを守る。Reeder Classic 5.5.1の滑らかな3カラム、落ち着いたダーク表示、Vim風のキーボード操作を読書体験の基準とする。機能の追加や設計に迷ったときは、ビジョンの「迷ったときの問い」に照らす。

**ループ**: 読む（3カラム・キー操作）→ メモする（気になる記事のAI要約をノートに送り、記事を見ながら自分の言葉で書く）→ AIに相談する（ノートを確認したうえでClaudeに渡す）→ 理解する（自分の言葉のノートが残る）。AIは端末内で要約を作るだけで、使わなくてもすべての操作ができる。

V1は本人のMacで使う。Backend、アカウント、複数端末同期は持たない。新規ライブラリは空で開始し、プロトタイプからのデータ移行は対象外（[決定0001](decisions/0001-fresh-library-no-prototype-migration.md)）。

ベータ間のデータ互換は保証しない。同じ版での保存・再起動による保持は維持し、1.0以降は更新・モデル変更をまたぐ保持を保証する。ライブラリの初期化がエラーを返した場合は起動エラーを示し、自動削除・作り直しをしない。非互換DBのSwiftData上の挙動は未検証。ベータ配布時は互換性の制約をリリースノートに明記する（[決定0003](decisions/0003-beta-data-compatibility.md)）。

## 2. 製品の約束

- 滑らかな3カラムとキーボード操作を提供し、フォーカス・読書位置・日本語入力・システムのアクセシビリティを保つ。
- 取得できる本文を読みやすく表示し、取得できないときもRSS要約と原文リンクで読書を続けられる。全文完全性は保証せず、入力カバー範囲を示す。
- 既読は閲覧履歴、Starは「あとで咀嚼したい」の印、ノートは自分の言葉で書く場所として区別する。ノートは、要約を送った記事の一覧と、1つのMarkdownの文書を持つ。
- 保持期間内の記事内容と、ノートはオフラインで読める。ノートに送った記事のタイトル・URL・RSS要約と、本人が書いた内容は自動削除しない。
- AIは端末内の要約だけで、使わなくてもすべてできる。AIが作った文章は、ノートの中で「AI要約」と分かる印を持つ。

## 3. V1の読書と理解

### 3.1 3カラムと読書操作

| カラム | 役割・表示 |
|---|---|
| 左 | Feeds（すべての記事・未読・Star）、ノート（最近編集した順・新しいノート）、購読元（フォルダ・購読元）の対象選択。購読元の横にサイトアイコン。購読元の区画は畳める。右上は右詰めで購読追加・更新の順。Hide Sidebarとフォルダ整理ボタンは置かない |
| 中央 | 選んだ対象の記事一覧（ノートでは、そのノートに要約を送った記事。まだ無ければ、送るとここに並ぶと示す）。記事は上段左に購読元、右に公開日時、下段にタイトル・要約・記事画像。境界のドラッグで幅を広げられる |
| 右 | 記事本文。ノートを選んだときは、ツールバーのボタン（`⌥⌘I`）で、ノートを記事の右に標準のインスペクタとして開閉でき、ノートを選ぶと初めから開く（幅は境界のドラッグで変えられ、次の起動でも保つ）。記事の上部ボタンはStar・ノートに要約を送る・外部ブラウザ（globe）。外観切替はSettingsのAppearance（システム／ライト／ダーク）に置く |

購読はRSS/Atom URLから追加する。追加時に未分類・既存の1階層フォルダを選ぶか、新しいフォルダ名を入力する。追加済み購読の右クリックで名前・フォルダ・移動・解除を操作する。フォルダの名前変更と記事の集約を提供し、複数購読に属する同じ記事・未読件数を重複計上しない。空フォルダ・入れ子は持たず、最後の購読が外れるとフォルダ表示も消える。

一覧の公開日時は今日なら時刻、過去なら日付と時刻、現在の年以外なら年も示す。日時不明は「—」とし、受信日時で補わない。未読はオレンジの印と明るい文字、既読は行全体を落ち着いた色にする。選択中は読みやすいコントラストを保つ。

| キー | 操作 |
|---|---|
| `j` / `k` | 次／前記事 |
| `s` | Starの付け外し |
| `n` | 現在の記事の要約をノートに送るメニューを開く（アイコンと同じ） |
| `m` | 既読／未読切替 |
| `b` | 元ページを既定の外部ブラウザで開く |
| `v` | 元ページをアプリ内で開く |
| `Esc` | 原文から同じ記事の記憶した読書位置へ戻る。ノートに送るメニューを閉じる |

原文中も`j/k/s/n`を使える。`j/k`または一覧クリックで別記事を選ぶと原文を閉じ、新しい記事の通常の読書表示に戻る。原文の開閉は右カラム内で行い、左・中央の幅と購読追加・更新ボタンを維持する。読み込み完了で本文領域の高さを変えない。Starやノートへの送信は現在の記事・読書位置を保ち、結果を示す。テキスト入力欄（ノートのエディタを含む）・IME変換・修飾キー付き操作では文字入力と標準操作を優先する。主要操作はキーボードだけでも完結する。外部ブラウザ内の操作は対象外。

次記事は下から上、前記事は上から下へ短く素早く入る。原文の開閉は、右から左へ入り右へ戻る短いスライド（本のページを進める向き）でつなぎ、Reduce Motionでは移動を無効にする。ノートとFeedsの往復でも同じ3カラムを保ち、Feedsへ戻ると対象・選択記事・読書位置を復元する。ノートは、最後に開いていた記事と、パネルの開閉・幅を復元する。

本文またはRSS要約が記事ペインに実表示された時点で初回既読日時を記録する。一覧スクロール・本文取得だけでは既読にしない。再受信・再表示でも初回日時を更新しない。全文取得に失敗してもRSS要約と原文リンクを示し、paywall・ログイン・robots制限などを回避しない。

RSS提供内容と抽出本文のリンク・引用構造を保持し、リンクはクリックして既定ブラウザへ開ける。引用は本文と区別し、本文カバー範囲は末尾に一度だけ控えめに示す。書式情報のない保存本文はテキストとして読める。「本文を再取得」で更新でき、失敗時は保存済み本文を保って失敗を示す。

### 3.2 Starとノートへの送信

**Star**は「あとで咀嚼したい」の印で、既読日時を変えない。現在の付与状態と付与日時を保存する。解除するとStar一覧から外れ、付け直すと新しい付与日時を使う。選択中の記事を解除しても次の移動までは表示と位置を保つ。本文が期限切れになっても、Star・タイトル・URLは保持する。Starはノートとは独立で、ノートへ送っても外しても互いを変えない。

**ノートに要約を送る**（[決定0019](decisions/0019-v1-simplification-notes.md)）。記事の上部のボタン（またはキー`n`）は、どの記事でも、Starの有無に関わらず使える。押すと短いメニューが開き、「新しいノート」と、最近編集したノート（最大8件）が並ぶ。選ぶとすぐ送り、本人は読み続けられる。送信の進行・結果（「『タイトル』に送りました」と「開く」）・失敗の理由は、画面に短く示す。送信は、押したときに選んだ記事とノートに結びつけ、記事を移っても取り違えない。既読日時とStarは変えない。

- **新しいノート**: 記事のタイトルを見出し（`# タイトル`）にし、続けて要約、出典行を置く。
- **既存のノート**: 末尾に、空行、要約、出典行を足す。同じ記事を同じノートへもう一度送ると、要約をもう一度足す（本人の操作なので）。
- **出典行**は`出典: タイトル <URL>`。要約をAIが作ったときは、行の終わりに「（AI要約）」を付ける。AIを使わない送信では、RSS要約（なければ要約なし）を要約として入れ、印は付けない。 If both title and URL are absent, AI output keeps its mark on its own line.
- 要約の作り方・長さ・形式・追加の指示は、Settingsの「要約」で選ぶ（第5.1節）。
- 本人が送信を押したので、AIの文章も確認なしで書き込む。ただし、メッセージの「取り消す」で、ノートがその後に変わっていなければ元に戻せる（送信で作った記事の記録も戻す）。Undo is offered for 8 seconds. If the note changed, pressing it reports that it cannot be undone and preserves the text. Ordinary editing remains available.保存に失敗したときは、成功と示さず、ノートを変えない。
- 本文が期限切れでAIの入力がない記事も、AIを使わない送信（タイトル・URL・RSS要約）はできる。

**記事とノートの紐づけ**は、送信だけで作られる（「ノートに入れる」だけの操作は無い）。送った時点の**タイトル・原文URL・保持しているRSS要約**を、そのノートの記事一覧に1件記録し、本文の期限切れ・購読解除の後も残す。抽出全文は複製しない。同じ記事を同じノートへ再度送っても、記録は重複しない。記事は複数のノートに入れられる。一覧の記事は右クリックの「このノートから外す」で外せる。外すのは記録だけで、ノートの文章は変わらず、記事・Starも変わらない。記録の保存失敗は成功扱いにせず、ノートを変えない。

### 3.3 ノートと保持・削除

**ノート**は、1つのMarkdownのテキスト文書で、複数持てる。サイドバーに、最近編集した順に並び（フォルダ分けはV1後）、「新しいノート」で作る。タイトルは本文の最初の空でない行から、先頭の`#`と空白を除いたもの（空なら「新規ノート」）で、別の名前の欄は持たない。長さの上限はなく、`#`で始まる行は見出し、`-`で始まる行はリストとして扱える。入力のたびに保存し、入力した文字を整えず、そのまま保存する。保存失敗を成功扱いにせず、IME変換中の入力を妨げない。ゴール・タグ・フォルダ・検索・入れ子は持たない。

ノートを選ぶと、中央にそのノートの記事一覧、右に記事、その右にノートのパネル（エディタ）が開く。パネルは、ツールバーのボタンか`⌥⌘I`で開閉でき、記事を読みながら書ける。パネルを開くとき、ウィンドウが4つの領域に足りないほど狭いときだけ、サイドバーを畳む（標準の分割ビューの動作で、Reduce Motionでは動きを省く。しきい値は約1,300pt。実機の測定から決めた仮の値）。パネルの幅は境界のドラッグで変えられ、次の起動でも保つ。選んだ記事とスクロール位置は、ノートごとに1つで、パネルを開閉しても変わらない。`j`/`k`・`s`・`n`・`b`・`v`・`m`は、編集できる欄（ノートを含む）に入力していないときだけ働き、IME変換中は働かない。ノートの中でも、`⌥⌘↓`（次）と`⌥⌘↑`（前）で記事を移れる。Star・ノートに送る・ブラウザで開くは、右に表示中の記事に対して働く。ノートのパネルのヘッダーには、Claudeへの依頼などを置く共有ボタンがある（第5.2節）。

ノートの削除は確認を取り、そのノートの本文と記事の記録を消す。削除は取り消せない。記事・Star・他のノートは変えない。エディタはプレーンなMarkdownの文字を編集し、システムの文字サービス・元に戻す・日本語入力を使える。エディタは、`#`で始まる行（見出し。`#`は1〜6個で、後ろに空白か行末）を太く大きく、`-` `*` `+` または番号（`1.` `1)`）で始まる行（リスト。行頭の空白は8個まで）を記号に色を付け、折り返した行を文字の位置に揃えて見せる。これは表示だけで、保存される文字は一切変わらず、Enterでリストを続けたり、引用符・ダッシュを置き換えたりしない。貼り付けとドロップはプレーンテキストだけを入れる。日本語の変換中は整形せず、確定か取り消しの後に整える。太字・斜体・コード・表・チェックリスト・プレビューはV1後。ノートの文章は、AIや他の操作が本人の操作なしに書き込まない。例外は、本人が「ノートに要約を送る」を押したときの1回の書き込みだけである。

記事本文・RSS要約は初期30日、Settingsで7 / 30 / 90 / 365日から選ぶ。未読は初回受信、既読は初回既読を起算点とし、再受信・再表示で期限を延長しない。短縮時・本文一括削除時は対象を確認する。期限切れ本文・要約は自動削除し、削除状態と原文リンクを残す。

ノートの全文と、ノートに送った記事のタイトル・URL・記録したRSS要約は、記事の期限切れ・本文削除・購読解除でも保持する。ノートの削除は、本人の明示操作と確認による。ノートへ送ることは元記事全文の期限を延長せず、期限切れ全文をオフライン閲覧やAI入力に復活させない。ノートに記録した要約は、別の所有データとして一覧に表示できる。

### 3.4 Faviconとサムネイル

購読元のFaviconと記事画像を区別する。RSS/Atomが提供する記事画像を優先し、はてなブックマークでは記事画像メタデータを使う。中央と右の読書表示に利用可能な画像を示す。画像なし・取得失敗・オフラインでも読書を止めず、非同期画像の到着で行高・選択・スクロール位置を変えない。再利用用のキャッシュを持つが、ノートの保存契約には含めない。

## 4. 製品判断の軸

読書の連続性、開いたことと関心の区別、本人が選ぶ記録、入力範囲の正直な表示を優先する。取得成功率を上げるために制限を回避したり、欠けた本文を推測で補ったりしない。個人の読書履歴をサーバーへ預けることを前提にせず、AIの提案も本人が確認して自分の言葉にする。

## 5. AIの使い方

### 5.1 端末内AI（記事の要約）

AIは端末内のモデルだけで動かし、外部通信・アカウント・APIキーを使わない。アプリが自動でシステム資産の取得などの通信を起こさない（[決定0009](decisions/0009-on-device-ai-principles.md)）。AIの機能は**記事の要約をノートに送ること**だけで、本人が「ノートに要約を送る」（第3.2節）を押したときだけ動く。何もしなければ何も作らない。The S2 plan ([PR #69](https://github.com/ojiman/feeeder/pull/69)) approves an unmarked RSS-summary/source fallback for an unavailable model, refusal, failure, blank answer or the 20-second deadline. The message states what was sent. Cancellation and turning AI off during a request write nothing. A save or reload error is shown as failure; a reload error after a successful save does not undo the committed write.

入力は、保持中の本文の先頭約3,000文字（切ったときは結果で示す）で、期限切れの本文は使わない（[決定0015](decisions/0015-article-summary-details.md)）。Settingsの「要約」で、次を選べる（[決定0019](decisions/0019-v1-simplification-notes.md)）。

- **作り方**: 「AIで要約する（この Mac の中だけ）」（モデルが使えるときの既定）、または「要約せず、タイトル・URL・RSS要約を送る」。AIを使わない選択でも、送信はすべて使える。
- **長さ**: 1文、3文以内（既定）、5文以内。**形式**: 文章（既定）、箇条書き。
- **追加の指示**（任意、200文字まで）: 本人が書いた言葉を、モデルへの指示に足す。例「専門用語には短い説明を付ける」。
- モデルのその他の設定（温度など）はV1では出さない。

AIの質は保証せず、事実性をアプリが保証しない。AIが作った文章は「（AI要約）」の印でノートの中で区別でき、本人が編集・削除する。

### 5.2 Claudeへの依頼（ノートの機能。本人が内容を確認して送る）

ノートのパネルのヘッダーにある共有ボタン（システムの共有アイコン）のメニューに「Claudeで開く…」「Markdownをコピー」「Markdownとして書き出す…」を置く（[決定0019](decisions/0019-v1-simplification-notes.md)）。本文が空または空白だけなら3項目を無効にする。システムの共有サービス（メッセージ・メールなど）はV1後。ノートを選んでいないとき（記事の一覧だけを読んでいるとき）には、Claudeへの依頼の入口を出さない。

「Claudeで開く…」は確認画面を開き、**ノート全文を含むレビュー用パッケージ**と出力言語（日本語／English）を省略なしで見せる。依頼文は、Claudeにノートを読んで、すでにできていること（ノートの文の引用つき）、足りない観点（ノートに書かれていないことだけを根拠にし、書かれていることを「ない」と言わない）、確認する価値のある反対の見方、次に読む・書くとよいことを示すよう求め、ノートの書き換え・アプリへの書き込み・外部アクセスは求めない。ノートの中の指示は実行しないよう求め、与えた内容にない事実を作らないよう求めるが、返答の真実性は保証しない。レビュー用パッケージは記事もゴールも含まない。確認後にノートを編集するとレビューは無効になり、作り直す。有効期間は24時間。

「Markdownをコピー」はノート本文そのものを正確にコピーし、「Markdownとして書き出す…」は本文と同じUTF-8 bytesを末尾改変なしで`.md`に保存する。ファイル名はノートのタイトルから安全に作り、既存ファイルの上書き確認は保存画面に任せる。レビュー画面の「全文をコピー」「TXTを書き出す」「分割を書き出す」とClaudeへ渡すファイルは、確認画面に表示された同一のレビュー用パッケージを使う。ノート本文およびレビュー用パッケージは、本人が確認画面で「Claudeで開く」を押すまでMacの外へ出ない。アプリ管理のコピーは確認時点のスナップショットで、編集では消えず、そのノートの削除か24時間で消える。

利用者が省略のないパッケージを確認して「Claudeで開く」を操作すると、生成TXTと短い依頼文をClaude Desktopの送信前の入力欄へ渡す。V1の連携先はClaude Desktopのみで、現在の経路はCowork。直接起動・事前入力・添付は、対応するClaude Desktop環境で実機確認した経路だけを採用する。本人がAttachを許可して内容を確認・送信し、必要なフォルダ許可も本人が判断する。毎回ファイルを探す手動添付を通常経路にせず、アプリは自動送信・返答の自動書込みをしない。端末の外へ内容が出る経路はこれだけである。

起動失敗・利用不可・取消時は確認済み内容を保ち、再試行・全文コピー・TXT書き出しへ戻れる。長さ制約だけを理由に本文・出典を黙って省略しない。添付制限時は内容を保つ分割などの別経路と制約を示し、利用者が選べる。コピーや書き出しだけで直接起動・添付の受入条件を満たしたことにしない。

アプリ管理コピーの期限・削除と、検証済みClaude環境は[Architecture §3](architecture.md#3-ai端末内の提案とclaudeハンドオフ)に定める。本人の書き出し先とClaude側に渡った内容は、アプリの自動削除対象外。

## 6. 制約と対象外

- macOS 27.0以降（サポート下限。CIのビルド下限は26.6のまま。[決定0007](decisions/0007-support-floor-macos-27.md)）。Backend、アカウント、同期、サーバー側巡回・AI処理、共有ノート、push通知はV1の対象外。
- 入れ子／空フォルダ、ノートのフォルダ・階層・タグ・検索・ゴール、時間軸（日次・週）のノート、システムの共有サービス（メッセージ・メールなど）はV1の必須範囲外。旧プロトタイプのLikeとその互換・移行は対象外で、Starは別の新しい関心の印。
- paywall、購読制、ログイン、captcha、robots制限の回避、全文完全性の保証は行わない。
- アプリ内BYOK/API生成、端末外のAI（Private Cloud Computeなど）、Claude Desktop以外への専用連携、AIの自動送信・記録・事実性保証は対象外。
- アプリ内の表示言語・タイムゾーン設定は対象外。AI依頼の出力言語選択は含む。
- ソースはApache-2.0。LICENSEと必要な第三者ライセンス・著作権表示・NOTICEを同梱し、記事・feed・商標・サービス規約にはFeeederのライセンスを適用しない。
- 公開対象はコード・仕様・合成サンプル／テストだけ。本人の購読・履歴・取得記事・ノート・認証情報を含めず、公開前に差分と履歴を確認する。ソース公開は製品受入後の別判断。App Store公開・署名配布はV1の受入条件ではなく、方針の承認を公開・配布操作の許可とは扱わない。
- エージェント開発の境界と検証は[Architecture §4](architecture.md#4-aiエージェントによる開発)に定める。指示文だけでOSの隔離が成立したとは扱わない。

### 7.1 1.0の出荷条件

- 保存スキーマを`VersionedSchema`として固定する。
- 1.0リリースタグを起点とする合成ストアの保持検証をCIへ必須で組み込む。購読・記事・既読・Star・ノートを新版で開き、再openして保持を確認する。未実行・スキップを成功扱いにせず、以後のモデル変更でも継続する。
- Bundle ID、保存先、署名・sandbox構成を確定して保存・再起動・更新を検証する。ベータDBを開けるか確認し、開けない場合の退避案内を用意する。
- 配布物のversion・build番号・署名・案内・ZIP・hashの作成を再現可能にし、CIのad hoc開発ビルドとの違いを示す。

## 8. V1後の候補

本人の不便が確認された場合だけ検討する。完了条件・実装の約束ではない。

- 端末外のAI（BYOKなど）による下書き支援（採用する場合は新しい決定記録で扱う）、表示言語／タイムゾーン設定、Claude以外の同等の直接起動・添付連携。
- ノートの見た目の整形の拡張（表・チェックリスト・プレビュー）、ノートのフォルダ・検索・タグ、AIによるノートの編集支援、システムの共有サービス、時間軸の振り返りビュー、URLコピー。

Backend・同期は必要性が生じた時点で製品判断からやり直す。
