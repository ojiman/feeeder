## 1. 目的と対象利用者

長年RSSを使う熟練ユーザーが、Macで多くの記事を気持ちよく読み分け、ザッピングでStarして拾った記事を関心のテーマごとに整理し、ノートに自分の言葉で書きながら理解を深めるためのリーダー。Reeder Classic 5.5.1の滑らかな3カラム、落ち着いたダーク表示、Vim風のキーボード操作を読書体験の基準とする。AIは端末内で提案するだけで、使わなくてもすべての操作ができる。

V1は本人のMacで使う。Backend、アカウント、複数端末同期は持たない。新規ライブラリは空で開始し、プロトタイプからのデータ移行は対象外（[決定0001](decisions/0001-fresh-library-no-prototype-migration.md)）。

ベータ間のデータ互換は保証しない。同じ版での保存・再起動による保持は維持し、1.0以降は更新・モデル変更をまたぐ保持を保証する。ライブラリの初期化がエラーを返した場合は起動エラーを示し、自動削除・作り直しをしない。非互換DBのSwiftData上の挙動は未検証。ベータ配布時は互換性の制約をリリースノートに明記する（[決定0003](decisions/0003-beta-data-compatibility.md)）。

## 2. 製品の約束

- 滑らかな3カラムとキーボード操作を提供し、フォーカス・読書位置・日本語入力・システムのアクセシビリティを保つ。
- 取得できる本文を読みやすく表示し、取得できないときもRSS要約と原文リンクで読書を続けられる。全文完全性は保証せず、入力カバー範囲を示す。
- 既読は閲覧履歴、Starは「あとで咀嚼したい」の印、テーマは関心ごとに記事を束ね、学習ゴールを置き、1つのノートに自分の言葉で書く場所として区別する。
- 保持期間内の記事内容と、テーマ・ノートはオフラインで読める。テーマに入れた記事のタイトル・URL・RSS要約と、本人が書いた内容は自動削除しない。
- AIは端末内の提案だけで、採用と文章は本人が決める。AIを使わずにテーマ・ノートを作成・編集できる。

## 3. V1の読書と理解

### 3.1 3カラムと読書操作

| カラム | 役割・表示 |
|---|---|
| 左 | Feeds（すべての記事・未読・Star）、テーマ（未整理のStar・各テーマ・新しいテーマ）、購読元（フォルダ・購読元）の対象選択。購読元の横にサイトアイコン。購読元の区画は畳める。右上は右詰めで購読追加・更新の順。Hide Sidebarとフォルダ整理ボタンは置かない |
| 中央 | 選んだ対象の記事一覧（テーマでも常に記事一覧。テーマの上部にゴールを置く）。記事は上段左に購読元、右に公開日時、下段にタイトル・要約・記事画像。境界のドラッグで幅を広げられる |
| 右 | 記事本文。テーマでは、ツールバーのボタン（`⌥⌘I`）で、ノートを記事の右に標準のインスペクタとして開閉できる（幅は300〜640pt、ドラッグで変えられる）。記事の上部ボタンはStar・テーマに入れる・外部ブラウザ（globe）。AIの入口はテーマ、外観切替はSettingsのAppearance（システム／ライト／ダーク）に置く |

購読はRSS/Atom URLから追加する。追加時に未分類・既存の1階層フォルダを選ぶか、新しいフォルダ名を入力する。追加済み購読の右クリックで名前・フォルダ・移動・解除を操作する。フォルダの名前変更と記事の集約を提供し、複数購読に属する同じ記事・未読件数を重複計上しない。空フォルダ・入れ子は持たず、最後の購読が外れるとフォルダ表示も消える。

一覧の公開日時は今日なら時刻、過去なら日付と時刻、現在の年以外なら年も示す。日時不明は「—」とし、受信日時で補わない。未読はオレンジの印と明るい文字、既読は行全体を落ち着いた色にする。選択中は読みやすいコントラストを保つ。

| キー | 操作 |
|---|---|
| `j` / `k` | 次／前記事 |
| `s` | Starの付け外し |
| `t` | 現在の記事を入れるテーマの選択を開く（アイコンと同じ） |
| `m` | 既読／未読切替 |
| `b` | 元ページを既定の外部ブラウザで開く |
| `v` | 元ページをアプリ内で開く |
| `Esc` | 原文から同じ記事の記憶した読書位置へ戻る。テーマの選択を閉じる |

原文中も`j/k/s/t`を使える。`j/k`または一覧クリックで別記事を選ぶと原文を閉じ、新しい記事の通常の読書表示に戻る。原文の開閉は右カラム内で行い、左・中央の幅と購読追加・更新ボタンを維持する。読み込み完了で本文領域の高さを変えない。Star・テーマへの追加は現在の記事・読書位置を保ち、結果を示す。テキスト入力欄・IME変換・修飾キー付き操作では文字入力と標準操作を優先する。主要操作はキーボードだけでも完結する。外部ブラウザ内の操作は対象外。

次記事は下から上、前記事は上から下へ短く素早く入る。原文の開閉は、右から左へ入り右へ戻る短いスライド（本のページを進める向き）でつなぎ、Reduce Motionでは移動を無効にする。テーマとFeedsの往復でも同じ3カラムを保ち、Feedsへ戻ると対象・選択記事・読書位置を復元する。テーマは、最後に開いた面（記事／問い）を復元する。

本文またはRSS要約が記事ペインに実表示された時点で初回既読日時を記録する。一覧スクロール・本文取得だけでは既読にしない。再受信・再表示でも初回日時を更新しない。全文取得に失敗してもRSS要約と原文リンクを示し、paywall・ログイン・robots制限などを回避しない。

RSS提供内容と抽出本文のリンク・引用構造を保持し、リンクはクリックして既定ブラウザへ開ける。引用は本文と区別し、本文カバー範囲は末尾に一度だけ控えめに示す。書式情報のない保存本文はテキストとして読める。「本文を再取得」で更新でき、失敗時は保存済み本文を保って失敗を示す。

### 3.2 Starとテーマ

**Star**は「あとで咀嚼したい」の印で、既読日時を変えない。現在の付与状態と付与日時を保存する。解除するとStar一覧・未整理のStarから外れ、付け直すと新しい付与日時を使う。選択中の記事を解除しても次の移動までは表示と位置を保つ。解除・本文期限切れでテーマの記録を変更せず、期限後もStar・タイトル・URLを保持する。

**テーマ**は、名前・**学習ゴール**・1つの**ノート**・記事を持つ。学習ゴールは、そのテーマで何を学びたいかを書く任意のプレーンテキストで、1段落・200文字まで（改行は空白に直し、超える入力は黙って切らずに断る。入力欄は文字を切らず、200文字を超えると文字数が赤くなって保存を待つ）。名前とゴールは1つのシートで作成・編集し、記事一覧の上とノートのパネルの上部に表示する。記事は複数のテーマに入れられる。入れる操作は`t`キーと記事ツールバーのアイコン（ドラッグ&ドロップも候補）で、どちらも同じ選択を開く。選択には、近い既存テーマ（端末内AIが使えるとき）、既存テーマの一覧、新しいテーマ名の入力がある。入れる操作は既読日時とStarを変えない。**Starとは独立**で、Starを付けなくても入れられ、Starを外してもテーマには残る。**未整理のStar**は、Starが付いていてどのテーマにも入っていない記事で、左カラムに件数を示す。

テーマに入れた時点の**タイトル・原文URL・保持しているRSS要約**を記録し、本文の期限切れ・購読解除の後も残す。抽出全文は複製しない。要約が無い場合はタイトル・URLだけにして欠如を示す。同じ記事を同じテーマへ再度入れても重複・上書きしない。保存失敗は成功扱いにせず再試行できる。

テーマは作成・名前変更・削除ができる。削除は確認を取り、そのテーマの記事の紐付けとノートを消す。記事そのもの・Star・他のテーマは変えない。記事をテーマから外しても記事は消えず、ノートは変わらない。空のテーマを作れる。入れ子のテーマは持たない。フォルダ（購読元の整理）とテーマ（関心の整理）は別の軸で、フォルダ内の記事を自動的にテーマにはしない。

### 3.3 ノートと保持・削除

テーマごとに**ノート**を1つ持つ。ノートは1つのプレーンテキストの文書で、長さの上限はなく、`#`で始まる行は見出しとして扱う（書式は付けない）。ノートは、テーマを選んだときのツールバーのボタンか`⌥⌘I`で、記事の右に標準のインスペクタとして開く（テーマの外ではボタンは押せない。ツールバーの高さは変わらない）。開くとサイドバーが畳まれ（標準の分割ビューの動作で、Reduce Motionでは動きを省く）、閉じると戻る。開いている間は、記事一覧の上のゴールの左のボタンで、サイドバーを戻したり畳んだりできる。ノートを開いたかどうかは、テーマごとに、アプリを開いている間だけ覚える（初めは閉じている）。パネルの上部には、テーマ名とゴール（押すと編集）、前の記事・次の記事の小さなボタンがある。選んだ記事とスクロール位置は、テーマごとに1つで、ノートを開閉しても変わらない。`j`/`k`・`s`・`t`・`b`・`v`・`m`は、編集できる欄（ノートを含む）に入力していないときだけ働き、IME変換中は働かない。ノートの中でも、`⌥⌘↓`（次）と`⌥⌘↑`（前）で記事を移れる。Star・テーマに入れる・ブラウザで開くは、右に表示中の記事に対して働く。ノートのカーソル位置は、ノートを閉じて開き直しても保たれる（メモリ上のみ）。ノートは入力のたびに保存し、入力した文字を整えず、そのまま保存する。保存失敗を成功扱いにせず、IME変換中の入力を妨げない。ノートは、AIや他の操作が自動で書き込まない。

**問い・答え・根拠・いまの理解からの移行**（[決定0014](decisions/0014-note-migration-format.md)）。この版を初めて開いたとき、各テーマについて、いまの理解、続いて問いごとに「`# 問い`」の見出し・答え・根拠の記事（`根拠の記事:`と、タイトルとリンクの一覧）をこの順で1つのノートにまとめる。まとめた結果が元の文章をすべて含むことを確かめ、1回の保存で、ノートの書き込みと古い問い・答え・いまの理解の削除を同時に行う。失敗したときは何も消さず、アラートで知らせて次の起動でやり直す。レンズの名前・回答済みの印・問いの日時は引き継がない。

記事本文・RSS要約は初期30日、Settingsで7 / 30 / 90 / 365日から選ぶ。未読は初回受信、既読は初回既読を起算点とし、再受信・再表示で期限を延長しない。短縮時・本文一括削除時は対象を確認する。期限切れ本文・要約は自動削除し、削除状態と原文リンクを残す。

テーマの名前・学習ゴール・ノート、およびテーマに入れた記事のタイトル・URL・記録したRSS要約は、記事の期限切れ・本文削除・購読解除でも保持する。テーマの削除は本人の明示操作と確認による。Star・テーマへの追加は元記事全文の期限を延長せず、期限切れ全文をオフライン閲覧やAI入力に復活させない。テーマに記録した要約は別の所有データとして利用できる。

### 3.4 Faviconとサムネイル

購読元のFaviconと記事画像を区別する。RSS/Atomが提供する記事画像を優先し、はてなブックマークでは記事画像メタデータを使う。中央と右の読書表示に利用可能な画像を示す。画像なし・取得失敗・オフラインでも読書を止めず、非同期画像の到着で行高・選択・スクロール位置を変えない。再利用用のキャッシュを持つが、テーマの永久保存契約には含めない。

## 4. 製品判断の軸

読書の連続性、開いたことと関心の区別、本人が選ぶ記録、入力範囲の正直な表示を優先する。取得成功率を上げるために制限を回避したり、欠けた本文を推測で補ったりしない。個人の読書履歴をサーバーへ預けることを前提にせず、AIの提案も本人が確認して自分の言葉にする。

## 5. AIの使い方

### 5.1 端末内AI

AIは端末内のモデルだけで動かし、外部通信・アカウント・APIキーを使わない。提案だけを出し、ノートへ自動で書き込まない。Settingsで無効にでき、モデルの利用不可・ガードレールの誤検知・入力量の超過では提案が出ないだけで、すべての操作を手動で続けられる。アプリが自動でシステム資産の取得などの通信を起こさない（[決定0009](decisions/0009-on-device-ai-principles.md)）。提案は次の5つ。

- **近いテーマ・まとまりの提案**: `t`で開く選択に、近い既存テーマを示す。「未整理のStar」では、まとまりそうな記事の束を示し、そこから新しいテーマを作れる。
- **テーマ名の案**: 新しいテーマの名前の候補。
- **記事の要約**（ノートのパネルだけ。[決定0013](decisions/0013-goal-and-note-for-themes.md)、[決定0017](decisions/0017-note-beside-the-article.md)）: パネルの「記事から要約する」を押したときだけ、いま右に開いている記事の要約（3文以内）を作る。作らせる・中止する・別の記事へ移るのいずれも本人の操作で、何もしなければ何も作らない。保持中の本文の先頭約3,000文字（切ったときは表示する）、本文がなければテーマに記録したRSS要約を使い、期限切れの本文は使わない。結果はパネルのカードに出し、「AIによる要約」「誤りを含むことがあります」を付け、「ノートに採用」を押したときだけ、選択範囲の後ろ（なければカーソル位置、どちらもなければノートの末尾）に独立した段落として、出典行（`出典: タイトル <URL>`）とともに挿入する。採用は本文のテキストビューへの1回の編集で、⌘Zで取り消せる。採用しない要約はどこにも保存しない。失敗・20秒の時間切れ・モデルの利用不可は短い文で知らせ、読書を妨げない。Settingsで端末内AIを切ると、このボタンを出さず、何も呼ばない。
- **ノートへのAI操作**（ノートのパネルだけ。[決定0016](decisions/0016-note-actions.md)）: ノートの下に「わかりやすく」「3行の要点」の2つのボタンを置く。選んだ文章、なければカーソルのある節（直前の`#`で始まる行から次の`#`の行の手前まで。見出しは含めない）に対して、押したときだけ1件のカードを作る。入力は最大1,300文字（「わかりやすく」はそれを超えると断り、「3行の要点」は先頭1,300文字を使って表示する）。学習ゴールは「3行の要点」にだけ渡す。「採用」は、書き直しなら対象の文章を置き換え、要点なら節の後ろに「・」で始まる3行を新しい段落として足す。1回の編集で、⌘Zで戻せる。カードは、ノートの文章か選択が変わると破棄し、採用できない。「別の案」「閉じる」がある。Settingsで端末内AIを切ると、このボタンの列を出さず、何も呼ばない。

入力量には上限があり、超える場合は新しい記事から使う。まとまりの提案では、使った件数を示す（テーマ名の案は、新しい16件までに切るだけで件数は示さない。[決定0011](decisions/0011-on-device-generation-defaults.md)）。AIの入力は保持中の内容とテーマが記録した要約に限り、期限切れ全文は補完しない。提案の質は保証せず、本人が確認して採用する。

### 5.2 Claudeへの依頼（本人が内容を確認して送る）

テーマから、出力言語と含める出典を選び、ソースを個別に含める／除外する。一つの出典なら記事単位の依頼もできる。テーマに記録した要約と現在保持する記事内容を区別し、保存日時・カバー範囲・出典URLを確認できる。実際に含めた出典だけを示し、要約のみ・一部抽出を全文と誤認させない。本人の**ゴール**と**ノート**を含めるかを、それぞれのスイッチで選ぶ（[決定0018](decisions/0018-handoff-goal-note.md)）。ゴールは、あれば初期でオンで、ノートは、ツールバーの入口では初期でオフ（本人の書いた文章なので、含めると確認した内容のとおりMacの外へ渡ると画面に示す）。ノートのパネルの「Claudeでレビューを頼む」は、ゴールとノートをオンにして開く。中身が空のスイッチは、オフで押せない。ノートを含めると、依頼は「ノートをゴールに照らしたレビュー」になり、できていること（ノートの文の引用つき）、足りない観点（ノートに書かれていないことだけを根拠にし、書かれていることを「ない」と言わない）、出典に照らした根拠の弱い点と反対の見方、次に読む・書くとよいこと、を求める。ゴールかノートを含めるときは、記事の出典は1件も選ばなくてよい（その場合、有効期間は24時間）。どちらも含めないときは、出典が1件以上必要。レビュー後に、含めたゴール・ノートやテーマ名が変わると、レビューは無効になり作り直す。依頼文は与えた内容にない事実を作らないよう求めるが、返答の真実性は保証しない。

利用者が省略のないパッケージを確認して「Claudeで開く」を操作すると、生成TXTと短い依頼文をClaude Desktopの送信前の入力欄へ渡す。V1の連携先はClaude Desktopのみで、現在の経路はCowork。直接起動・事前入力・添付は、対応するClaude Desktop環境で実機確認した経路だけを採用する。本人がAttachを許可して内容を確認・送信し、必要なフォルダ許可も本人が判断する。毎回ファイルを探す手動添付を通常経路にせず、アプリは自動送信・返答の自動書込みをしない。端末の外へ内容が出る経路はこれだけである。

起動失敗・利用不可・取消時は確認済み内容を保ち、再試行・全文コピー・TXT書き出しへ戻れる。長さ制約だけを理由に本文・出典を黙って省略しない。添付制限時は内容を保つ分割などの別経路と制約を示し、利用者が選べる。コピーや書き出しだけで直接起動・添付の受入条件を満たしたことにしない。

記事由来のAI入力はその時点で保持する内容に限る。テーマに記録した要約は元記事の期限後も使えるが、期限切れ全文は補完しない。アプリ管理コピーの期限・削除と、検証済みClaude環境は[Architecture §3](architecture.md#3-ai端末内の提案とclaudeハンドオフ)に定める。本人の書き出し先とClaude側に渡った内容は、アプリの自動削除対象外。

## 6. 制約と対象外

- macOS 27.0以降（サポート下限。CIのビルド下限は26.6のまま。[決定0007](decisions/0007-support-floor-macos-27.md)）。Backend、アカウント、同期、サーバー側巡回・AI処理、共有ノート、push通知はV1の対象外。
- 入れ子／空フォルダ、入れ子のテーマ、時間軸（日次・週）のノート、URLコピー／標準ShareはV1の必須範囲外。旧プロトタイプのLikeとその互換・移行は対象外で、Starは別の新しい関心の印。
- paywall、購読制、ログイン、captcha、robots制限の回避、全文完全性の保証は行わない。
- アプリ内BYOK/API生成、端末外のAI（Private Cloud Computeなど）、Claude Desktop以外への専用連携、AIの自動送信・記録・事実性保証は対象外。
- アプリ内の表示言語・タイムゾーン設定は対象外。AI依頼の出力言語選択は含む。
- ソースはApache-2.0。LICENSEと必要な第三者ライセンス・著作権表示・NOTICEを同梱し、記事・feed・商標・サービス規約にはFeeederのライセンスを適用しない。
- 公開対象はコード・仕様・合成サンプル／テストだけ。本人の購読・履歴・取得記事・テーマ・認証情報を含めず、公開前に差分と履歴を確認する。ソース公開は製品受入後の別判断。App Store公開・署名配布はV1の受入条件ではなく、方針の承認を公開・配布操作の許可とは扱わない。
- エージェント開発の境界と検証は[Architecture §4](architecture.md#4-aiエージェントによる開発)に定める。指示文だけでOSの隔離が成立したとは扱わない。

## 7. 観察可能なV1受入シナリオ

以下は合格条件であり、実行済み・合格済みの一覧ではない。仕様の詳細は第3・5節と合わせて確認する。

| ID | 利用者シナリオ | 合格条件 |
|---|---|---|
| PRD-01 | 購読を整理し、滑らかに読む | 3カラム・外観・フォルダ／未読件数・キー操作・テーマとFeedsの往復が第3.1節どおり動く。本文取り違え・目立つ停止・スクロール飛びがなく、入力／IME・VoiceOver等を妨げない。PdMがReeder Classicと実機比較する |
| PRD-02 | 未読一覧から記事を開く | 一覧スクロールでは未読。本文／RSS要約の実表示で初回既読日時を記録する |
| PRD-03 | 全文取得に失敗した記事を読む | 読書を遮らず要約・カバー範囲・原文リンクを示し、制限を回避しない |
| PRD-04 | テーマで理解を深める | 第3.2・3.3節のとおり、テーマを作って（学習ゴールを書いてもよい）記事を入れ、ノートに自分の言葉で書ける。古い問い・答え・根拠・いまの理解は、失われずにノートへ移る。AIなしで完結し、再起動・オフライン・購読解除・本文期限後も記録を読める |
| PRD-05 | Claude Desktopへ依頼する | 第5.2節どおりレビュー後に未起動／起動済みClaudeへ依頼文と選択内容を渡し、本人のAttach後に添付状態となる。本人が送信する。省略・自動送信がなく、失敗時も再試行・コピー・書き出しへ戻れる |
| PRD-06 | AIの提案を扱う | 端末内AIの提案は編集できる下書きで、ノートへ自動で書き込まない。本人が採用・編集し、事実性をアプリが保証しない |
| PRD-07 | 最終デモをレビューする | PdM／本人が本表と製品範囲を実演確認し、明示的に承認する。それまでは製品受入としない |
| PRD-08 | 保持・削除を設定する | 第3.3節の期限・確認・テーマの非自動削除が成立する。期限切れ本文を読める／AI入力に使えると誤認させない |
| PRD-09 | Starを読み返す | キーとボタンが同じ状態を変更し、Star一覧を移動できる。解除後もテーマの記録を保ち、再起動・本文期限後もStar／タイトル／URLを保つ |
| PRD-10 | 読書中にテーマへ入れる | 通常／原文表示から`t`／アイコンでテーマへ入れ、選択・位置を保つ。Starと独立で、同じテーマへの再追加で重複・上書きをしない。期限・購読解除・再起動後も記録を保ち、保存失敗は再試行できる |
| PRD-11 | 多くの記事を読み分ける | フォルダ操作・重複しない集約・購読アイコン／記事画像が成立し、画像到着・失敗・オフラインで行高・選択・位置を変えない |
| PRD-12 | Starをテーマにまとめる | 「未整理のStar」から、`t`やまとまりの提案でテーマを作り記事を入れられる。提案は採用しなくてよく、まとまりの提案では使った件数と上限を示す。本人の実際のStarでの提案の質はPdMが確認する |
| PRD-13 | 端末内AIが使えない | 無効・利用不可・失敗でも、テーマ・ノートの作成が手動で完結し、アプリが通信を起こさない |

### 7.1 1.0の出荷条件

- 保存スキーマを`VersionedSchema`として固定する。
- 1.0リリースタグを起点とする合成ストアの保持検証をCIへ必須で組み込む。購読・記事・既読・Star・テーマ・ノートを新版で開き、再openして保持を確認する。未実行・スキップを成功扱いにせず、以後のモデル変更でも継続する。
- Bundle ID、保存先、署名・sandbox構成を確定して保存・再起動・更新を検証する。ベータDBを開けるか確認し、開けない場合の退避案内を用意する。
- 配布物のversion・build番号・署名・案内・ZIP・hashの作成を再現可能にし、CIのad hoc開発ビルドとの違いを示す。

## 8. V1後の候補

本人の不便が確認された場合だけ検討する。完了条件・実装の約束ではない。

- 端末外のAI（BYOKなど）による下書き支援（採用する場合は新しい決定記録で扱う）、表示言語／タイムゾーン設定、Claude以外の同等の直接起動・添付連携。
- 時間軸（週・月）の振り返りビュー、テーマの入れ子、URLコピー／macOS標準Share。

Backend・同期は必要性が生じた時点で製品判断からやり直す。
