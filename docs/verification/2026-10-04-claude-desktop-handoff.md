# Claude Desktop連携の技術検証（2026-10-04〜05）

## 判定

**この環境での連携経路の技術検証を完了し、PASSとする。公式ディープリンクでの起動・依頼文の事前入力・添付・送信前停止、ユーザーによる送信後の本文読取りとSHA-256一致、添付キャンセル後の再試行、不在ファイルの挙動を確認した。Feeeder本体の実装・異常時の復帰UI・他環境は未検証のため、PRD-05全体をPASSにはしない。**

`claude://cowork/new?q=…&file=…`を連携経路として採用する。今回の操作順は「Claudeを開く → Attachを許可 → 利用者が送信 → 親フォルダへのアクセスを許可 → 回答」だった。送信とは別に2回の許可操作が必要で、ファイルを探す操作は不要だった。ディープリンク由来の依頼文にはClaudeの赤い注意表示も出た。同じフォルダでも新しいセッションでは再び許可画面が出た。すべての版・設定で毎回出るとまでは一般化しないが、初回だけの操作とは案内しない。

## 再現経路と検証ツールの制約

[Claudeの公式案内](https://support.claude.com/en/articles/14729294-open-claude-desktop-with-a-link)のCoworkリンクを使った。生成済みURLをmacOSに直接渡すとClaudeへ到達した。通常チャット用の未文書化パラメータは試していない。

初回に作成した`.webloc`経由の起動は、ユーザーのTerminalで`_LSOpenURLsWithCompletionHandler()`の`-10400`エラーとなった。URLを直接`open`へ渡す方式で到達したため、製品実装では`.webloc`を介さずURLをOSへ渡す。

検証ツールから`file:`をブラウザで開く操作はブラウザのセキュリティポリシーで拒否された。エージェントによる迂回は行わず、各URLの起動とClaudeの通常終了はユーザーが実施した。エージェントはClaude UIの確認、合成ファイルのAttach許可、通常添付との比較、未送信の本文検証依頼文の準備と回答の照合を行った。

本文検証では、回答を入力欄に含めず、ファイルから5項目を答えるよう依頼した。得られた回答は`日本語`、`0500`・`END_A_20261004`、`https://source-b.example/article/2`・RSS要約のみ、`END_B_20261004`、`END_PACKAGE_20261004`で、元ファイルと一致した。Claudeの実行記録には、合成ファイルの親フォルダへのアクセス要求・許可と、そのファイルを`wc -c`・`cat`で読み取った出力が残っていた。ブラウザ検索や外部コネクタの利用は記録上確認されなかった。

## 実装・受入へ持ち越す事項

1. Feeederで確認済みパッケージを生成し、短い`q`と絶対パスの`file`をURLとしてOSへ渡す。Claude側のAttach、注意表示、送信後のフォルダ許可を利用手順で案内する。これらはClaude側のUIであり、確認を自動操作・回避することを製品の通常経路にしない。
2. 起動前に生成ファイルの存在・通常ファイルであること・読取り・確認済み内容との一致をFeeeder側で確認する。URLの起動成功や添付カードだけを成功証拠にしない。Feeeder実装後にも今回と同じ本文・出典・ハッシュの照合を行う。プレビューの失敗と本文読取りの失敗を区別する。
3. 起動不能・添付拒否・不在ファイル・上限超過時のパッケージ保持と再試行を、Feeeder実装後に確認する。コピー／手動添付だけを通常経路の代わりにはしない。未導入・未ログイン・プラン差・上限超過の実機確認は製品受入に含める。
4. 親フォルダへのアクセス許可はセッションでの読取り・変更も許し、クラウド実行でファイルが端末を離れる旨を表示した。選択したソースの生成パッケージだけを置いた専用の一時ディレクトリを渡し、ユーザーのライブラリや他のパッケージを同じディレクトリに置かない。本人が確認したパッケージを元の保存データから独立したコピーとして渡す。一時ファイルは送信後にClaudeが読むため、起動成功を理由に直ちに削除しない。保持期限と削除タイミングは実装設計で決め、期限切れ時の再生成は再確認を求め、元のソースも期限切れ等で利用できなければその旨を示す。`/private/tmp`は使い捨ての作業領域であり、機密データの隔離境界ではない。

Spikeの合成ファイルとURLは一時ディレクトリに置き、本番コード・依存関係・DB migrationは変更していない。ビルド／既存テストは実行対象外。文書の整合性と`git diff --check`を確認した。
