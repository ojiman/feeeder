# S1 Notes Implementation Plan

> **For agentic workers:** use superpowers:executing-plans (inline) to run this plan task by task. Delete this file in the PR that completes S1b ([roadmap](../../roadmap.md)).

**Goal:** Turn themes into plain Markdown notes ([decision 0019](../../decisions/0019-v1-simplification-notes.md), stage S1), in two PRs: **S1a** removes what V1 no longer has; **S1b** renames and fixes the layout.

**Architecture:** SwiftData stays. Both PRs change the schema by *removing* models and fields, or *renaming* the entity; an old store must still open, and feeds, articles, read state and Stars must survive. Notes and links made before may be lost (the owner accepted this: test data). Pure logic goes in ReaderCore with tests; views stay thin.

**Tech stack:** Swift 6.4, SwiftUI/AppKit, SwiftData, Swift Testing. No new dependency.

**Spec:** [specification.md](../../specification.md) §3.2, §3.3, §5; decision 0019 points 1, 2, 4, 7, 9, 10, 12.

## Global Constraints

- The macOS floor is 27.0 (support) and 26.6 (build). Use no API that needs the macOS 27 SDK.
- Every new mutating `ReaderStore` method calls `reloadIfNeeded()` first and has a save/reload failure-injection test. A failed save is never shown as success (AGENTS.md, Definition of done 7).
- The app never deletes or recreates an unreadable store; it shows the startup error.
- English commits, PR text and code comments. UI labels stay Japanese (quote them with an English gloss in docs).
- Tests use synthetic data. Run each UI suite alone (a whole run does not reliably report UI tests).
- One independent review of a fixed commit per PR (risky: store/model), using `docs/review-checklist.md`; one verification record, `docs/verification/s1-notes.md`, extended by S1b.

## Decisions for the PdM (merging this plan approves them)

1. **Two PRs.** S1 as one PR would touch about 60 files. S1a removes, S1b renames.
2. **Data.** S1a drops goals, questions and the understanding text (the model fields go; the note text and names stay). S1b renames the stored entity `Theme` to `Note`, so notes and links made before S1b are **not kept** (the owner said they are test data). Feeds, articles, read state and Stars are kept; a test proves it.
3. **The hand-off keeps working** until S3, without the goal: the package holds the note and the chosen articles. The review screen loses its goal switch.
4. **`t` and the picker stay** until S2 (they are the only way to link an article); their label becomes 「ノートに入れる」 in S1b.
5. **Kept without UI until S2:** `ArticleSummaryModel`, `ArticleSummaryPrompt` and `NoteInsertion` (S2 reuses them). Everything else of the summary card and the note actions is deleted.
6. **Fold rule.** The sidebar folds when a note panel opens **only if the window is narrower than 1,200 pt** (the minimum widths sum to 1,125 pt: 185 + 280 + 360 + 300). The number is a proposal; it is checked in a real window after S1b.
7. **Opening a note shows its first article** when the note has articles and none was selected, so the reader is not empty.

## Review Focus (checked deliberately in each review)

1. A store written by the previous version opens: feeds, articles, read state, Stars intact; no deletion of an unreadable store.
2. Deleting a note removes only its text and its records; failure paths do not report success; `try?` hides nothing.
3. Note titles: an empty note, only `#` marks, CRLF, emoji, a 10,000-character first line, a first line of spaces.
4. Opening the panel at once must not take keyboard focus (the keys `j`, `k`, `s`, `t` still work) and must not disturb Japanese input.
5. The hand-off package without the goal: no leftover goal text; managed copies made earlier (with goal metadata) still reconcile and are never opened if invalid.
