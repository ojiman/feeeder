# S4 Clean up: Implementation Plan

> **For agentic workers:** use superpowers:executing-plans (inline). Delete this file in the PR that completes S4 ([roadmap](../../roadmap.md)).

**Goal:** Remove the code and tests that nothing in the app reaches any more, so that the next agent reads only what is alive. **No behavior changes:** what the person sees, what is saved and what leaves the Mac stay the same, and a golden test proves it for the Claude package ([decision 0019](../../decisions/0019-v1-simplification-notes.md), stage S4).

**Architecture:** Four small slices, each a commit that builds and passes: (1) unused store and text helpers, (2) the article-source machinery of the package, (3) the managed-copy metadata and its maintenance, (4) documents. Nothing in the stored data (the SwiftData schema) changes.

**Tech stack:** Swift 6.4, Swift Testing. No new dependency.

**Spec:** [specification.md](../../specification.md) §5.2; decisions 0019 and 0021.

## Global Constraints

- No behavior change, no schema change, no new dependency. macOS floor 27.0 (support) and 26.6 (build): keep expressions short (the CI compiler, Swift 6.3.3, once timed out on a long test helper).
- The package for a note is byte for byte what it is on `main` (a golden test). A managed copy written by any earlier build is still safe: it is read leniently and removed when it expires or its note is deleted; no unrelated file is ever deleted; the symlink and path checks stay.
- Run the whole suite, then **each UI suite alone** (and a suite that touches layout several times); put the per-suite results in the record. English commits; tests use synthetic data.
- Risky enough for one independent review of a fixed commit (external write, deletion code) and one record, `docs/verification/s4-clean-up.md`.

## Decisions for the PdM (merging this plan approves them)

1. **Pure removal.** No screen, text or file format changes, except that a package no longer has a `Source IDs:` line in its split parts (it never had sources).
2. **Old managed copies** (made with articles or the old keys) are read leniently: unknown fields are ignored; they are removed at their own expiry (24 hours at most) or when their note is deleted. Their early removal is not required.
3. **A copy's lifetime** is the fixed 24 hours (the earlier "earliest article expiry" rule only mattered for article sources).
4. **Stored data is not touched.** `NoteArticle.title`, `url` and `summary` are recorded when an article is sent but no screen reads them (the note's text already holds the source line). Whether to drop the columns, or to show them for an article that was unsubscribed, is a separate decision for later.
5. Decision records and the old verification records are not edited.

## Review Focus (checked deliberately in the review)

1. **The same bytes:** the package text and its SHA-256 for the same note equal the golden values captured on `main` before the change (empty-ish notes, CRLF, emoji, a 1 MiB+ note, split parts and their headers except the removed `Source IDs:` line).
2. **Old copies:** a copy with articles and `selections`, one with the old `themeID`, one with `questionIDs`, one with an unknown future field, a damaged `metadata.json`, a symlinked folder: none fails maintenance forever, none deletes anything outside the managed folder, each is removed at expiry or with its note.
3. **No dead leftovers:** a search for `AISource`, `AIInputSelection`, `aiSources`, `toggleNote`, `adopted(`, `picker`, `theme` in `Sources` and `Tests` finds nothing (except decision records and the fixture script).
4. **Tests are not just deleted:** every behavior that is still alive keeps a test; a list of deleted tests with the reason for each is in the record.
5. **CI compiler:** nothing in the change needs a long type-check (the CI run is the final check; do not call the work done before it is green).
