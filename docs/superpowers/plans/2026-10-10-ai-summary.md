# N4: AI summary in the reader — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This project keeps one supervised implementer ([decision 0002](../../decisions/0002-single-supervised-writer.md)).

**Goal:** On a theme's note face, the person can ask the on-device model for a short summary of the article they are reading, read it next to their note, and adopt it into the note with one action. Nothing is created unless they ask, and nothing is saved unless they adopt it.

**Architecture:** A pure prompt builder with a fixed input budget (`ArticleSummaryPrompt`). A small `@MainActor` model (`ArticleSummaryModel`) that asks the existing `ThemeAssistant.generate` (so tests use a fake model), with a deadline, cancellation, and a request token so a late answer for another article is dropped. A pure `NoteInsertion` that computes the new note text for an adopt. A segmented switch [原文｜AI要約] in the reader's top bar (N3) and a summary card that replaces the reader's content while the switch is on 「AI要約」.

**Tech Stack:** Swift 6, SwiftUI, FoundationModels (through the existing `FoundationModelsGenerator`), Swift Testing. No new dependency, no new API above the macOS 26.6 build floor.

**Spec:** [decision 0013](../../decisions/0013-goal-and-note-for-themes.md) (points 5 and 6), [roadmap Part 1c, row N4](2026-10-10-theme-notes.md), [the experiment](../../verification/2026-10-10-note-ai-experiment.md), [decision 0009](../../decisions/0009-on-device-ai-principles.md). Merging this plan approves it. Plan approval is not product acceptance.

**Language:** New project text is in English (AGENTS.md, "Language"). App labels stay Japanese; they are quoted as they appear, with a short English gloss.

## Decisions for you (merging approves them)

1. **Where it is and what the switch means.** On the note face only, the reader's top bar gets a segmented switch 「原文｜AI要約」 (Original text | AI summary). 「原文」 is the article as it is shown today (not the web page; `v` still opens the web page). The articles face is unchanged. The switch stays where you put it when you move to another article, but the summary does not: each article needs its own request.
2. **Only on request.** In 「AI要約」 the card shows a button 「要約を作る」 (Make a summary). Nothing is generated by opening the face, choosing an article, or switching to 「AI要約」. A request can be cancelled (「中止」), and moving to another article or back to 「原文」 cancels it and drops its answer.
3. **What the model reads.** The retained article body, cut to its first **3,000 characters** (about 2,200 tokens by the measured 0.74 tokens per character, so the whole request stays near 3,300 of the 4,096 the model has; decision 0013's budget). When the body is cut, the card says 「長い記事のため、最初の約3,000文字から要約しました」. If the body is gone but the RSS summary that the theme recorded for this article is still there, the model reads that and the card says so (「テーマに記録したRSS要約から作りました」). If neither exists (the text expired or was never held) the card says 「この記事の本文は保持期限を過ぎているため、要約できません」 and nothing is sent. Expired text is never used (decision 0013).
4. **What it produces.** A plain summary of at most three sentences (the experiment's best format). Not the three-point list: it inverted a meaning in the experiment. The card is labelled 「AIによる要約」 with the line 「誤りを含むことがあります。原文で確かめてください。」 and a link 「原文を見る」 that switches back to 「原文」. The output is capped at 400 tokens.
5. **Adopting.** A button 「ノートに採用」 (Adopt into the note) inserts the summary into the note, as its own paragraph, **after the end of your selection (or at the cursor)**, never over your text. Below the summary it adds one source line `出典: <title> <url>` (the same list format as the migration; no link if the article has none). If the note is empty it becomes the first text. After adopting, the button reads 「採用しました」 and is disabled until a new summary is made. The summary is saved nowhere else. Undo with ⌘Z is **not promised** in this PR (the insertion goes through the same save as typing; making it undoable needs a native text bridge, which is PR 10's decision).
6. **Failure never blocks reading.** Any failure (guardrail, context overflow, model error, a deadline of **20 seconds**, cancellation) becomes a short message 「要約を作れませんでした。もう一度試すか、原文を読んでください。」 with 「もう一度」 (Try again). The switch back to 「原文」 always works.
7. **When AI is off or unavailable.** If the Settings switch for on-device AI is off, the 「原文｜AI要約」 switch is **not shown** and nothing is called. If it is on but the model is unavailable, the switch is shown and the card explains: 「この Mac では端末内AIを使えません」 or 「言語モデルの資産がありません。システム設定で取得できます」 (the app never downloads it). The state is read again at the moment of the request and again when the answer arrives.
8. **Not in this PR.** Note actions (N5), the hand-off with the note (N6), summaries on the articles face, a cache of summaries, the three-point format, translation, and undo for adopting.

## Global Constraints

- Support floor macOS 27.0; build floor and CI stay macOS 26.6 / Swift 6.3.3. No macOS 27-only API: use character limits, not `tokenCount(for:)`. No method references as `Binding` setters; no mutated captured `var` in `@MainActor` closures in tests.
- Decision 0009: no network, no system asset download, no automatic write to the note, the Settings switch is respected, prompts are not logged. Text the model produced reaches the note only through the adopt action.
- A failed save of the adopted text is shown and never reported as success; the person's note is unchanged (AGENTS.md, Definition of done 7).
- Tests use synthetic data and a fake assistant only. One theme per PR. Failing tests first. Commit and PR text in English. Add the attribution line the session gives. Do not push to `main`, sign, or release. After implementation and one independent review of a fixed commit, push the branch and open the PR without asking.
- UI tests: a whole `swift test` run does not reliably run every UI test (see [the N3 record](../../verification/2026-10-10-theme-two-panes.md)). Put new UI tests in a suite of their own, run each alone, and say which ran how.

## Review Focus

1. An answer that arrives after the person moved to another article, switched to 「原文」, left the note face, or turned AI off must not appear and must not be adoptable → Task 2.
2. A body with emoji, combining marks or CRLF at the 3,000-character cut must be cut on a character boundary and never mid-grapheme → Task 1.
3. Adopting into an empty note, at the cursor in the middle, with a selection, at the very end without a trailing line break, with CRLF text → Task 3; a failed save leaves the note as it was and shows an error → Task 4.
4. No article text, an expired article, an article with only the theme's recorded RSS summary → Task 2.
5. Pressing 「要約を作る」 twice, and cancelling, must not leave a second request running or a stuck "working" state → Task 2.

- [ ] **Step 1: Write the failing tests.** (a) A short body: `wasCut == false`, the prompt contains the title and the whole body, `maximumTokens == 400`. (d) The cut counts `Character`s: 2,999 plain characters followed by `👨‍👩‍👧` (one character, many scalars) and more text: the family emoji is kept whole or dropped whole, never split. (g) Line breaks inside the title are folded to one line. (h) The instructions tell the model to write at most three sentences, to use only what the article says, not to strengthen or reverse what is hedged or negated, and to keep numbers; they are fixed text (compare against a literal in the test so a change is deliberate).

### Task 2: The summary model

**Files:**
- Create: `Sources/ReaderCore/ArticleSummaryModel.swift`
- Test: `Tests/ReaderCoreTests/ArticleSummaryModelTests.swift`

**Interfaces:**
- Consumes: `ThemeAssistant.generationAvailability()` / `generate(_:)`, `ReaderStore.content(articleID:at:)`, `ReaderStore.themeArticles`, `withDeadline`.
- Produces:

```swift
@Observable @MainActor public final class ArticleSummaryModel {
    public enum State: Equatable, Sendable {
        case idle
        case working
        case ready(Summary)
        case unavailable(Reason)          // AI off, no text, unsupported, assets missing
        case failed
    }
    public struct Summary: Equatable, Sendable { public let articleID: UUID; public let text: String; public let wasCut: Bool; public let fromThemeSummary: Bool }
    public enum Reason: Equatable, Sendable { case disabled, noText, unsupported, assetsMissing }
    public private(set) var state: State
    public init(store: ReaderStore, assistant: (any ThemeAssistant)?, isEnabled: @escaping @MainActor () -> Bool, deadline: Double = 20, now: @escaping () -> Date = { .now })
    public func request(articleID: UUID, themeID: UUID?)   // starts at most one request; replaces a running one
    public func cancel()                                   // working -> idle
    public func reset()                                    // any state -> idle (article changed, mode left)
}
```

- [ ] **Step 1: Write the failing tests** with a fake assistant (a class with a scripted result, an optional delay, a call counter, and a flag that ignores cancellation, like the one in `ThemeSuggestionModelTests`). (a) Success: `.working` then `.ready` with the cleaned text (control characters and wrapping quotes removed, trimmed). (b) AI setting off: no call at all, `.unavailable(.disabled)`. (c) The setting turns off while the request is running: the answer is dropped, `.unavailable(.disabled)`. (d) `generationAvailability` is `.unsupported` or `.assetsMissing`: no generate call, the matching reason. (e) The model throws, returns blank text, or exceeds the deadline (a fake that never returns, `deadline: 0.05`): `.failed`, and the model can be used again. (f) `reset()` or a request for another article while working: the old answer, even if it arrives later, is not shown; a fake that ignores cancellation is also dropped. (g) `cancel()` goes to `.idle` and the late answer is dropped. (h) Two quick `request` calls for the same article: one result, the first request is cancelled (the call counter and the final state show it). (i) No retained text and no theme summary: `.unavailable(.noText)` and no call; an article whose body expired but whose `ThemeArticle.summary` is non-blank: a call with the theme's summary, `fromThemeSummary == true`; the theme's summary is used only when `themeID` is given and the article is a member. (j) A long body: `wasCut == true`. (k) The store is never written: `themeArticles`, every `Theme.note`, and the article read state are the same before and after, and no save is made (`saveHook` count stays zero).
- [ ] **Step 2: Run, see them fail. Step 3: Implement** (request token compared on return and after the awaits; the setting is read before the call and again on return).
- [ ] **Step 4: Run again.** Expected: pass. **Step 5: Commit** (`feat: ask the on-device model for an article summary, on request only (N4)`).

### Task 3: Adopting into the note

**Interfaces:**
- Produces:

```swift
public enum NoteInsertion {
    /// The text for an adopted summary: the summary, then `出典: <title> <url>` (no url part without a link).
    public static func summaryBlock(summary: String, title: String, url: String?) -> String
    /// `offset` is a character offset into `note` (the end of the selection, or the cursor), clamped to 0...note.count.
    /// The block becomes its own paragraph: one blank line before it unless it is at the start, one line break after it,

```

- [ ] **Step 1: Write the failing tests** with whole-string comparisons: empty note; start; middle of a paragraph (the insertion goes to the end of that paragraph's line? — rule: at the offset, but the block starts on its own line, so a mid-line cursor puts a line break first); end without a trailing line break; end with one; before an existing blank line (not doubled); offset out of range is clamped; CRLF notes keep their own line breaks and the block uses `\n` only if the note has no `\r\n`, otherwise `\r\n`; an emoji and combining marks around the offset are not split; the returned cursor offset is the end of the inserted block. The source line with a title that has line breaks is folded to one line; a blank title uses the url alone.
