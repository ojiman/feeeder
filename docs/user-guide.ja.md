# Unagi Reader ユーザーガイド（日本語）

[README](../README.md)から移した、操作・データ保持・Claude Desktop連携・検証手順の詳細です。内容はREADME分割前の日本語版を移したものです。英語版は[user-guide.md](user-guide.md)です。内容を変えるときは、両方を同じPRで更新するか、遅れているほうをPRに書いてください。製品の概要は[README](../README.md)を参照してください。

macOS 27.0以降向けのRSSリーダー。SwiftUI / AppKitで表示し、SwiftDataへ端末内保存します。アカウント・Backend・同期はありません。Star・ノート（要約を送った記事を束ね、自分の言葉で書く Markdownのメモ帳）・フォルダ・画像表示を実装しています。製品は「ノート」を中心にした形へ簡素化中です（[ビジョン](vision.md)、決定0019）。ゴール・端末内AIの提案・ノートの書き直しは、すでに無くなりました。実機受入と最終PdM判断は継続中です。

## 起動

XcodeのSwiftツールチェーンで、プロジェクトルートから実行します。SwiftPMが固定版のSwiftSoup 2.13.9を解決します。

```sh
bash scripts/build-app.sh release
```

生成される `.build/UnagiReader.app` をFinderから開いてください。ad hoc署名されたローカル開発用アプリです。Developer ID署名・公証は行いません。releaseの中間出力は `/private/tmp/feeeder-v1-release`、debugは `/private/tmp/rss-reader-build` に置きます。debug buildは引数を省略できます。

通常起動は空ライブラリから開始します。V1の保存先は `Application Support/UnagiReader/Reader.store`。同じ版での再起動では購読・記事・既読日時・Star・ノートを保持します。旧版の日次ノート・週ノート・スクラップは、ノート中心の版へ移行されず、**この版の初回起動で削除されます（元に戻せません）**。更新前に、下の手順で`UnagiReader`フォルダを退避してください（ベータ間の互換は保証しません）。ベータ中はバージョン更新をまたぐデータ保持を保証せず、1.0以降は保証します。旧スキーマのDBは開けない場合があります。初期化がエラーを返した場合は「ライブラリを開けませんでした」と表示し、アプリによる自動削除・作り直しは行いません。非互換スキーマでのSwiftDataの挙動は未検証です。ベータ配布時のリリースノートにもこの制約を記載します。過去のリリースノートの保持検証は、その版での結果であり、以後のベータ間の互換性保証ではありません。プロトタイプのデータ移行はありません。

以前の「テーマ」（学習ゴール・名前・ノート・記録した記事、問い・答え・「いまの理解」）は、この版へ移りません。購読・記事・既読・Starは残ります。**この版の初回起動で、以前のテーマの内容は使えなくなり、元に戻せません。** 更新前に、`UnagiReader`フォルダを退避してください。

旧名「Feeeder」のときのアプリを使っていた場合：名前が「Unagi Reader」に変わり、ライブラリは`Application Support/UnagiReader/`に置かれます。`Application Support/Feeeder/`はもう読みません。そのため、新しいビルドは空のライブラリで始まり、設定（ノートのパネル幅や要約の設定など）も初期値に戻ります。ライブラリを引き継ぐには、次のようにします（実機では未確認です）。

1. 古いアプリと新しいアプリを終了します。
2. Finderで`~/Library/Application Support/`を開きます（移動 → フォルダへ移動）。
3. 空の`UnagiReader`フォルダがすでにあれば、`UnagiReader-empty`などへ名前を変えます。
4. `Feeeder`フォルダの名前を`UnagiReader`に変えます。
5. Unagi Readerを起動し、購読とノートを確認してから、何かを削除してください。

ベータの更新後に開けず、新しい空ライブラリで使い直す場合は、本人の操作で次のように退避します。この手順自体の実機確認は未実施です。

1. Unagi Readerを⌘Qで終了します。
2. Finderの「移動 → フォルダへ移動」で `~/Library/Application Support/` を開きます。
3. `UnagiReader`フォルダ全体を、例えば`UnagiReader-backup-20261007-2100`へ名前変更して残します。`Reader.store`と、存在する場合の`Reader.store-shm`／`Reader.store-wal`は同じ組として退避し、DBファイルだけを抜き出さないでください。フォルダにはノートやHandoffの管理データも含まれます。
4. Unagi Readerを起動すると、新しい`UnagiReader`フォルダと空ライブラリを作ります。退避したフォルダは確認が済むまで残してください。退避はデータの変換・復元を保証するものではありません。

合成デモは保存先と挿入を明示して起動します。

```sh
open -n '.build/UnagiReader.app' --args --data-directory /private/tmp/feeeder-demo --seed-demo
```

`--data-directory <path>` は開発検証用の保存先指定です。`open -n`で新しいインスタンスを起動し、操作前にプロセス引数と合成購読の表示を確認してください。詳細は[AGENTS.md](../AGENTS.md)を参照してください。合成デモの `.example` URLに実在ページはありません。実際の購読・記事・ノートをGitへ追加しないでください。

## 操作

- 左はFeeds（すべての記事・未読・Star）／ノート（最近編集した順）／購読元（フォルダ・購読）の対象切替、中央は記事一覧（ノートではそのノートに入れた記事）、右は読書、の3カラム。ノートを選ぶと、記事の右にノートのパネルが開きます。外観はシステム追従・ライト・ダークから選べます。
- 左カラム右上の「＋」へRSS/Atom URLを入力し、未分類・既存フォルダを選ぶか、新しいフォルダ名を入力して購読。その右隣が更新ボタンです。手動XMLと合成サンプルも取り込めます。購読の右クリックで名前・1階層フォルダ・移動・解除を操作します。フォルダ選択で配下の記事を集約し、フォルダの右クリックで名前変更・統合ができます。
- 起動・復帰・稼働中30分ごとに更新し、ツールバーから手動更新できます。通信失敗でも保存済み記事を読み続けられます。
- 一覧にフォーカスして `j` / `k` で移動、`m` で既読／未読を切り替えます。一覧のスクロールでは既読にせず、本文またはRSS要約の実表示で初回既読日時を記録します。
- `s`でStarを付け外し、Star一覧から読み返せます。`n`（または右上の「ノートに要約を送る」）で、「新しいノート」か最近編集した8件のノートを選びます。↑/↓で選び、Returnで送信、Escで閉じます。新しいノートは記事タイトルの見出しから始まり、既存ノートは末尾へ要約と出典を追記します。記事も関連付けます。同じ記事を再送すると追記は増えますが、関連付けは1件です。Starとは独立しています。
- 送信結果の「取り消す」は8秒間使えます。ノートが変わっていなければ、この送信が作った内容と関連付けだけを戻します。編集済みなら取り消せないと知らせ、文章を保ちます。AI処理中は「中止」で書き込みを止められ、読み続けられます。ノートの記事一覧の右クリック「このノートから外す」は関連付けだけを外し、本文・Starを変えません。`t`と旧選択UIは削除しました。
- `b` で外部ブラウザ、`v` でアプリ内の原文、`Esc` で読書へ戻ります。原文閲覧は指定サイトへ通信し、アプリ内ブラウザはログイン状態を保存しません。原文中も`j/k/s/n`を使え、入力欄と修飾キー付きの操作を優先します。
- 本文抽出はbest effortです。「フィード提供本文」「抽出本文・全文保証なし」「RSS要約のみ」を区別します。取得不可なら要約と原文リンクを残し、制限を回避する取得は行いません。
- サイドバーの「ノート」に、ノートが最近編集した順に並びます。「新しいノート」を押すと、空のノートができ、すぐ選ばれてパネルが開きます。ノートの名前はなく、**本文の最初の行がタイトル**です（先頭の「#」と空白は除きます。空のときは「新規ノート」）。ノートを選んでも、中央は記事一覧のままで、右に選んだ記事が出ます。ノートのパネルは、ノートを選ぶと初めから開きます。ツールバーのボタンまたは`⌥⌘I`で閉じる／開けます（閉じたノートは、アプリを開いている間は閉じたままです）。ノートは、1つの文書で、自分の言葉でMarkdownのテキストを書きます。「#」で始まる行（1〜6個のあとに空白）は見出しとして太く大きく表示されます。「-」「*」「+」や「1.」のような番号で始まる行はリストで、記号に色が付き、折り返した行は文字の位置に揃います。変わるのは見た目だけで、保存される文字は変わらず、Returnでリストが続くこともありません。他のアプリからの貼り付け・ドロップは、プレーンテキストだけが入ります。日本語の変換中は、確定か取り消しをするまで見た目を整えません。長さの上限はなく、入力のたびに入力したまま保存されます。ウィンドウが狭い（約1,300pt未満）ときだけ、パネルを開くとサイドバーが畳まれて場所が空きます（記事一覧の上の左の小さなボタンで、また表示／畳めます。閉じるとサイドバーが戻ります）。パネルの幅は境界のドラッグで変えられ、次の起動でも覚えます（実機で確認中です）。パネルの上には共有ボタンと、前の記事・次の記事の小さな矢印があります。共有メニューには「Claudeで開く…」「Markdownをコピー」「Markdownとして書き出す…」があります。本文が空または空白だけのときは、3つの項目を無効にします。`j`/`k`で記事一覧を移り、`s`・`n`・`b`・`v`・`m`も記事一覧と同じように使えますが、ノートや入力欄に入力していないときだけで、日本語の変換中は働きません。書いている最中は、ノートの中でも`⌥⌘↓`（次の記事）と`⌥⌘↑`（前の記事）が使えます。本人が要約送信を選んだときだけAI要約を書き込み、自分の文章を書き直しません。右クリックの「削除…」でノートを削除できます（記事とStarは消えません）。
- 端末内AI: このMac内だけで計算し、外部へ送りません。Settingsの「要約」に「AIで要約する（この Mac の中だけ）」、長さ（1文／3文以内／5文以内）、形式（文章／箇条書き）、追加の指示（本人の言葉、1行200文字まで）、状態表示があります。資産を自動取得しません。AI要約は出典行に「（AI要約）」と示します。AIオフ・利用不可・失敗・空の応答・20秒の時間切れでは、保持中のRSS要約と出典、またはタイトルとURLだけを送り、結果で知らせます。処理中にAIを切った場合は書き込みません。保存・再読み込みの失敗は成功と示しません。保存後の再読み込みだけが失敗した場合は書き込みが残るため、再送前にノートを確認してください。
- 一覧にFaviconと利用可能な記事サムネイル、本文上に画像を表示します。画像はベストエフォートで、取得中・失敗でも表示枠の高さを変えません。キャッシュは64MiB、成功7日・失敗10分、同時取得4件までです。
- 記事本文・RSS要約は初期30日、Settingsで7 / 30 / 90 / 365日へ変更できます。未読は初回受信、既読は初回既読が起算点。保持短縮・本文一括削除は対象を確認して実行します。ノートの本文と、ノートに入れた記事の記録（タイトル・リンク・記録した要約）は自動削除しません。Starとノートへの追加は本文の期限を延長しません。

## Claude Desktop連携

ノートパネル上部の共有ボタンが唯一の入口です。メニューには3つの操作があります。

- 「Claudeで開く…」は確認画面を開きます。含まれるのはノートだけです。全文、依頼文、出力言語、サイズ、有効期限、SHA-256を確認できます。依頼文は、できていることをノートから引用し、足りない点はノートに書かれていない内容だけを根拠に示し、確認する価値のある反対の見方と次に読む・書くことを求めます。ノート内の指示を実行せず、推測・書き換え・Unagi Readerへの書き込みをしないよう求めます。記事・出典の選択欄はありません。
- 「Markdownをコピー」はノート本文そのものを正確にコピーします。「Markdownとして書き出す…」は同じUTF-8 bytesを、タイトルから作った安全な`.md`ファイル名で保存します。既存ファイルの確認は保存画面が行います。末尾の改行を足さず、Claudeにも送りません。

確認画面の「全文をコピー」、TXT・分割書き出し、Claudeへ渡すファイルは、すべてプレビューに表示された同一のレビュー用パッケージです。画面を開いたままノートを編集すると確認は無効になり、コピー・書き出し・Claude起動ができません。作り直して内容を確認してください。確認画面で「Claudeで開く」を押すまでは、内容はMacの外へ出ません。
確認対象は **Claude Desktop 2.19675.0 / Pro / Cowork**。通常Chatへの自動添付、他版・他プランは未検証です。アプリは短い依頼文とTXTのパスを起動リンクへ渡し、ノート本文はTXT内に保持します。

Claude側の **Attach確認** と **本人による送信** が必要です。送信後に別のフォルダ許可が出る場合があります。この許可はフォルダ内の読取り・変更を可能にし、cloudで使われるファイルは端末を離れます。Unagi Readerは生成パッケージと管理metadataだけを専用フォルダに置きます。リンク由来の依頼文に注意表示が出る場合もあります。起動成功は、添付完了・送信・読取り成功を意味しません。

取消・起動失敗時は同じレビュー内容で再試行でき、全文コピー・TXT書き出しも使えます。制限時は1MiB以下のUTF-8分割ファイルを書き出せます。この分割サイズはClaudeの対応上限を示す値ではありません。

アプリ管理コピーは、そのノートを削除したとき、または生成から24時間で削除します。後からノートを編集しても、確認時点のスナップショットとして期限まで残ります。記事の保持期限や削除・ノートからの取り外しは、コピーに影響しません。古いコピーもノートのIDがあればその削除に従い、最大24時間で失効します。古い記事・問いの項目は読み飛ばします。本人が指定した書き出し先と、Claude側に渡った内容は削除の対象外です。返答をノートへ貼り付ける操作は本人が行います。自動送信・返答の自動書き込みはありません。

## 検証と仕様

```sh
swift test --scratch-path /private/tmp/feeeder-dogfooding-build
```

ベータ中のCIは回帰テストとReleaseビルドの2並列です。`docs/**`またはMarkdownだけの変更ではCIを省略します。CIのZIPはad hoc署名された開発ビルドで、Developer ID署名・公証・自動Release公開を行わず、配布済みベータのZIPとは異なります。CIのビルドをMacで試すときは、ブラウザで保存せず `bash scripts/fetch-ci-app.sh <PR番号>` を使ってください（macOSと、ログイン済みの最近の`gh`が必要です）。ブラウザで保存したファイルには隔離属性が付き、公証のないアプリはビルドのたびにmacOSに止められます。`gh`で取得すると付かず、PRのheadと一致するビルドかを確認し、署名を検証し、合成データ用の起動コマンドを表示します。ブラウザで保存した場合に止められたときは、システム設定の「プライバシーとセキュリティ」から「このまま開く (Open Anyway)」を選んでください。管理者パスワードが必要です。ベータ間の保持検証はCIの対象外で、通常の`swift test`ではfixture未指定の保持試験だけスキップします。手動で検証する場合は次を実行します。

```sh
bash scripts/prepare-v1-store-fixture.sh /private/tmp/feeeder-v1-fixture-new
FEEEDER_V1_FIXTURE_DIR=/private/tmp/feeeder-v1-fixture-new swift test --scratch-path /private/tmp/feeeder-dogfooding-build
```

fixture生成先は存在しないディレクトリを指定します。配布済みベータの固定commitで合成DBを作り、新スキーマで開いて保持を検証します。1.0出荷時にはスキーマを`VersionedSchema`として固定し、1.0リリースタグを起点とする保持検証をCIへ組み込みます。テストは合成RSS/HTMLと一時DBを使います。[PRD](specification.md)、[Architecture](architecture.md)、今回の受入記録（Git履歴）に仕様・検証結果・未確認事項を記録しています。Reeder Classicを参考にした操作感のPdM判断、V1全体の受入は未完了です。
