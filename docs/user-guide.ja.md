# Unagi Reader ユーザーガイド（日本語）

[README](../README.md)から移した、操作・データ保持・ノートの外への出し方・検証手順の詳細です。内容はREADME分割前の日本語版を移したものです。英語版は[user-guide.md](user-guide.md)です。内容を変えるときは、両方を同じPRで更新するか、遅れているほうをPRに書いてください。製品の概要は[README](../README.md)を参照してください。

macOS 27.0以降向けのRSSリーダー。SwiftUI / AppKitで表示し、SwiftDataへ端末内保存します。アカウント・Backend・同期はありません。Star・ノート（自分の言葉で書く Markdownのメモ帳）・フォルダ・画像表示を実装しています。製品は簡素化中です（[ビジョン](vision.md)、決定0019・0049）。ゴール・端末内AIの提案・要約・Claudeへの受け渡しは、すでに無くなりました。実機受入と最終PdM判断は継続中です。

## 起動

XcodeのSwiftツールチェーンで、プロジェクトルートから実行します。SwiftPMが固定版のSwiftSoup 2.13.9を解決します。

```sh
bash scripts/build-app.sh release
```

生成される `.build/UnagiReader.app` をFinderから開いてください。ad hoc署名されたローカル開発用アプリです。Developer ID署名・公証は行いません。releaseの中間出力は `/private/tmp/unagi-reader-v1-release`、debugは `/private/tmp/unagi-reader-debug` に置きます。debug buildは引数を省略できます。

通常起動は空ライブラリから開始します。V1の保存先は `Application Support/UnagiReader/Reader.store`。同じ版での再起動では購読・記事・既読日時・Star・ノートを保持します。旧版の日次ノート・週ノート・スクラップは、ノート中心の版へ移行されず、**この版の初回起動で削除されます（元に戻せません）**。更新前に、下の手順で`UnagiReader`フォルダを退避してください（ベータ間の互換は保証しません）。ベータ中はバージョン更新をまたぐデータ保持を保証せず、1.0以降は保証します。旧スキーマのDBは開けない場合があります。初期化がエラーを返した場合は「ライブラリを開けませんでした」と表示し、アプリによる自動削除・作り直しは行いません。非互換スキーマでのSwiftDataの挙動は未検証です。ベータ配布時のリリースノートにもこの制約を記載します。過去のリリースノートの保持検証は、その版での結果であり、以後のベータ間の互換性保証ではありません。プロトタイプのデータ移行はありません。

以前の「テーマ」（学習ゴール・名前・ノート・記録した記事、問い・答え・「いまの理解」）は、この版へ移りません。購読・記事・既読・Starは残ります。**この版の初回起動で、以前のテーマの内容は使えなくなり、元に戻せません。** 更新前に、`UnagiReader`フォルダを退避してください。

ベータの更新後に開けず、新しい空ライブラリで使い直す場合は、本人の操作で次のように退避します。この手順自体の実機確認は未実施です。

1. Unagi Readerを⌘Qで終了します。
2. Finderの「移動 → フォルダへ移動」で `~/Library/Application Support/` を開きます。
3. `UnagiReader`フォルダ全体を、例えば`UnagiReader-backup-20261007-2100`へ名前変更して残します。`Reader.store`と、存在する場合の`Reader.store-shm`／`Reader.store-wal`は同じ組として退避し、DBファイルだけを抜き出さないでください。フォルダにはノートやHandoffの管理データも含まれます。
4. Unagi Readerを起動すると、新しい`UnagiReader`フォルダと空ライブラリを作ります。退避したフォルダは確認が済むまで残してください。退避はデータの変換・復元を保証するものではありません。

合成デモは保存先と挿入を明示して起動します。

```sh
open -n '.build/UnagiReader.app' --args --data-directory /private/tmp/unagi-reader-demo --seed-demo
```

`--data-directory <path>` は開発検証用の保存先指定です。`open -n`で新しいインスタンスを起動し、操作前にプロセス引数と合成購読の表示を確認してください。詳細は[AGENTS.md](../AGENTS.md)を参照してください。合成デモの `.example` URLに実在ページはありません。実際の購読・記事・ノートをGitへ追加しないでください。

## 操作

- 左はFeeds（すべての記事・未読・Star）／購読元（フォルダ・購読）の対象切替、中央は記事一覧、右は読書、の3カラム。ノートは1つで、どの画面でも、ツールバーのボタンか`⌥⌘I`で記事の右にパネルとして開きます。外観はシステム追従・ライト・ダークから選べます。
- 他のリーダーからの引っ越しは、メニューの「ファイル ▸ OPMLを取り込む…」でOPMLファイルを選びます。購読はすぐに並び、記事はあとから順に届きます。すでにある購読は変えません。`http://` の購読は、アプリが `http://` に接続できないため、`https://` に変えて取り込みます。フォルダは1階層で、深い階層は最上位のフォルダにまとまります。
- 左カラム右上の「＋」へRSS/Atom URLを入力します（`http://` で始まるURLは `https://` で確認します。サイトのURLでもかまいません。ページが示すフィードを探して使い、見つけたフィードのURLを欄の下に出します）。入力が止まると（貼り付けはすぐ）、アプリがそのURLを確認し、欄の下に「✓ フィード名」か、できなかった理由が出ます。「追加」はフィードを読めたときだけ押せます（Returnでも追加できます）。フォルダがあるときは、フィードを読めた後にフォルダの欄が出ます。何もせずReturnなら未分類に入り、名前を打つと候補が絞られ、まだ無い名前は「作って追加」で新しいフォルダになります（↑↓で選べます）。フォルダの行の＋から開いたときは、そのフォルダに入るので欄は出ません。入力の途中（ホスト名が完成して見えないURL）は送りません。すでに購読しているURLは、そう表示して追加しません。購読を右クリックして「フォルダへ移動…」を選ぶと、入力欄つきの小さな画面が開きます。打つと既存のフォルダが絞り込まれ、まだ無い名前なら「作って移動」を選べます（↑↓で選び、Returnで移動、Escで閉じます。「未分類」へも戻せます）。購読の移動は、サイドバーで購読をフォルダの行へドラッグしても行えます。移すと、行がなめらかに動き、移した先のフォルダが開きます（「購読元」の見出しへドラッグすると未分類に戻ります）。その右隣が更新ボタンです。障害確認用のXML直接入力と合成サンプルは、⌥を押しながら「＋」を開いたときだけ出ます。購読の右クリックで更新・名前の変更（行の中でその場で。選んだ行でReturnでも）・フォルダへ移動・解除を操作します。フォルダ選択で配下の記事を集約し、フォルダの右クリックで名前変更・統合ができます。
- 起動・復帰・稼働中30分ごとに更新し、ツールバーから手動更新できます。更新中は更新ボタンの矢印が回り、新しい記事は一覧の上から滑り込んで古い行を下へ押し出します（一覧をスクロールしているときは、読んでいる位置を動かしません。手動でも自動でも同じ動きで、Reduce Motionでは動かしません）。通信失敗でも保存済み記事を読み続けられます。
- 一覧にフォーカスして `j` / `k` で移動、`m` で既読／未読を切り替えます。一覧のスクロールでは既読にせず、本文またはRSS要約の実表示で初回既読日時を記録します。
- `s`でStarを付け外し、Star一覧から読み返せます。
- `b` で外部ブラウザ、`v` でアプリ内の原文、`Esc` で読書へ戻ります（原文は、右から入りながら、左のサイドバーが左へ畳まれ、原文が広く使えます。ページ左上の「×」・`Esc`・別の記事の選択で閉じると、原文が右へすべり出て、サイドバーが戻ります）。原文閲覧は指定サイトへ通信し、アプリ内ブラウザはログイン状態を保存しません。原文中も`j/k/s/n`を使え、入力欄と修飾キー付きの操作を優先します。
- 記事を開くと、フィードが提供する本文（なければRSS要約）がそのまま出ます。詳しい内容は「v」（アプリ内で原文）か「b」（ブラウザ）で見られます。「全文を取得」を押すと、原文のページから本文を取り込んで表示します（ページのメニューなどが混ざることがあります）。以前の版が取り込んだ本文（自分で「本文を再取得」したものも含む）は、初回の起動で消えます。フィードにまだある記事は、フィードの本文に戻り、そうでない記事は「全文を取得」で取り直せます。
- 本文抽出はbest effortです。「フィード提供本文」「抽出本文・全文保証なし」「RSS要約のみ」を区別します。取得不可なら要約と原文リンクを残し、制限を回避する取得は行いません。
- ノートは1つだけです。ツールバーのノートのボタン、`⌥⌘I`、または`n`キー（ノートや入力欄に入力していないとき）を押すと、右にノートのパネルが開きます。このとき、左のサイドバーと記事の一覧が約0.3秒の動きで左へ畳まれ、左が記事、右がノートになります（記事の一覧がある画面なら、どこでも同じノートです。もう一度押すと、逆の動きで元の画面に戻ります。選んだ記事と読んでいた位置は変わりません。初めは閉じています）。記事の左上の「一覧」ボタンを押すと、一覧が出て、左から一覧・記事・ノートの3つが並びます（もう一度押すと隠れます）。どちらの形でも`j`/`k`で次・前の記事へ移れます。Reduce Motionでは動かさずに切り替えます。ノートに名前はなく、ノートの一覧も、新規作成も、削除もありません。以前の版で複数のノートを作っていた場合は、この版の最初の起動で、最後に編集した1つだけが残り、ほかのノートと「ノートに入れた記事」の記録は消えます（元に戻せません）。ノートは、1つの文書で、自分の言葉でMarkdownのテキストを書きます。「#」で始まる行（1〜6個のあとに空白）は見出しとして太く大きく表示されます。「-」「*」「+」や「1.」のような番号で始まる行はリストで、記号に色が付き、折り返した行は文字の位置に揃います。変わるのは見た目だけで、保存される文字は変わらず、Returnでリストが続くこともありません。他のアプリからの貼り付け・ドロップは、プレーンテキストだけが入ります。日本語の変換中は、確定か取り消しをするまで見た目を整えません。長さの上限はなく、入力のたびに入力したまま保存されます。アプリがノートに文章を書き込むことはありません。パネルの幅は境界のドラッグで変えられ（ドラッグで閉じることはできません）、次の起動でも覚えます（実機で確認中です）。パネルの上には、前の記事・次の記事の小さな矢印と、「Markdownをコピー」のボタンがあります（本文をそのままコピーします。本文が空または空白だけのときは使えません）。`s`・`b`・`v`・`m`も記事一覧と同じように使えますが、ノートや入力欄に入力していないときだけで、日本語の変換中は働きません。書いている最中は、ノートの中でも`⌥⌘↓`（次の記事）と`⌥⌘↑`（前の記事）が使えます。
- AI: アプリは、自前のAIを持ちません（要約・提案・書き込み・AIサービスとの通信はしません）。ノートのエディタで使えるWriting Toolsと、ノートのコピーは、「ノートを他のAIと使う」にあります。
- 一覧にFaviconと利用可能な記事サムネイル、本文上に画像を表示します。画像はベストエフォートで、取得中・失敗でも表示枠の高さを変えません。キャッシュは64MiB、成功7日・失敗10分、同時取得4件までです。
- 記事本文・RSS要約は初期30日、Settingsで7 / 30 / 90 / 365日へ変更できます。未読は初回受信、既読は初回既読が起算点。保持短縮・本文一括削除は対象を確認して実行します。ノートの本文は自動削除しません。Starは本文の期限を延長しません。

## ノートを他のAIと使う

アプリは、自前のAIを持たず、Claude・Codex・Geminiなど、どのAIとも通信しません。

- **書くとき:** Apple Intelligenceが使えるMacでは、文字を選んで右クリックすると、システムのWriting Tools（校正・書き直し・口調・要約・要点・リスト・表など）がノートのエディタに出ます。これはシステムの機能で、アプリのものではありません。
- **他のAIに聞くとき:** ノートのパネル上部の「Markdownをコピー」を押します。ノート本文がそのままクリップボードに入るので、好きなAIへ貼り付けます。アプリは、ほかのアプリを起動せず、ファイルを作らず、通信しません。
- 本人が貼り付けない限り、Macの外へは何も出ません。
- 以前の版は、ライブラリのフォルダの`Handoffs`にノートのコピーを作っていました。アプリは起動時に、そのフォルダを削除します。

## 検証と仕様

```sh
swift test --scratch-path /private/tmp/unagi-reader-dogfooding-build
```

ベータ中のCIは回帰テストとReleaseビルドの2並列です。`docs/**`またはMarkdownだけの変更ではCIを省略します。CIのZIPはad hoc署名された開発ビルドで、Developer ID署名・公証・自動Release公開を行わず、配布済みベータのZIPとは異なります。CIのビルドをMacで試すときは、ブラウザで保存せず `bash scripts/fetch-ci-app.sh <PR番号>` を使ってください（macOSと、ログイン済みの最近の`gh`が必要です）。ブラウザで保存したファイルには隔離属性が付き、公証のないアプリはビルドのたびにmacOSに止められます。`gh`で取得すると付かず、PRのheadと一致するビルドかを確認し、署名を検証し、合成データ用の起動コマンドを表示します。ブラウザで保存した場合に止められたときは、システム設定の「プライバシーとセキュリティ」から「このまま開く (Open Anyway)」を選んでください。管理者パスワードが必要です。ベータ間の保持検証はCIの対象外で、通常の`swift test`ではfixture未指定の保持試験だけスキップします。手動で検証する場合は次を実行します。

```sh
bash scripts/prepare-v1-store-fixture.sh /private/tmp/unagi-reader-v1-fixture-new
UNAGI_READER_V1_FIXTURE_DIR=/private/tmp/unagi-reader-v1-fixture-new swift test --scratch-path /private/tmp/unagi-reader-dogfooding-build
```

fixture生成先は存在しないディレクトリを指定します。配布済みベータの固定commitで合成DBを作り、新スキーマで開いて保持を検証します。1.0出荷時にはスキーマを`VersionedSchema`として固定し、1.0リリースタグを起点とする保持検証をCIへ組み込みます。テストは合成RSS/HTMLと一時DBを使います。[PRD](specification.md)、[Architecture](architecture.md)、今回の受入記録（Git履歴）に仕様・検証結果・未確認事項を記録しています。Reeder Classicを参考にした操作感のPdM判断、V1全体の受入は未完了です。
