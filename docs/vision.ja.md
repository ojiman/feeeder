# ビジョン

このページは、Unagi Readerが何のためにあるかを、オーナー（PdM）の言葉で固定したものです。機能・設計・優先順位に迷ったとき、ここへ戻ってください。短くしてあります。詳細は[仕様書](specification.md)、各判断の理由は[決定記録](decisions/README.md)にあります。英語版は[vision.md](vision.md)です。2つは同じ内容に保ちます。

Unagi Readerは製品名です。リポジトリ・コード・アプリのバンドルは、名前の変更（ロードマップのステージD）までFeeederのままです。

## 一言で

大量の記事の中から、本当に重要な記事を見つけ、自分の価値に変える。

## 誰のためか

2026年のITエンジニア。毎日多くのフィードを読み分ける人。Reeder Classicを知っていて、滑らかな読み心地が最低ラインの人。

## 課題

読み切れないほど記事が書かれています。流し読みは簡単でも、理解は難しい。多くのリーダーは「読んだ」と「Star」で止まり、Starは溜まるだけです。メモアプリやAIチャットへ切り替えると、読む流れが切れます。しかも、読んだ履歴が他人のサーバーに渡ることも多い。

## 提供価値：1つのアプリの中の、待たされない1つのループ

**読む → メモする → AIに相談する → 理解する。**

- **読む。** キー操作のできる滑らかな3カラム。スクロールや入力は、再読み込み・通信・AIを待たない。
- **メモする。** ボタン1つで、記事の要約をノートに送る。送った記事はノートの隣に並び、記事を見ながら自分の言葉で書ける。
- **AIに相談する。** 自分が選んだときだけ、ノートの全文を確認して、Claudeに渡してレビューを頼む。
- **理解する。** 残るのは、プレーンなMarkdownの、自分の言葉のノート。自分のMacの中に。

滑らかな使い心地は、価値の一部です。最後に足す磨きではありません。

## 約束

1. **データは自分のMacに残る。** アカウント・バックエンド・同期はない。文章がMacの外へ出るのは、正確な内容を読んでボタンを押したときだけ。
2. **AIは下書き、決めるのは本人。** AIは端末内で動く。AIが書いた文章はノートの中で印が付き、取り消せる。AIを切っても、すべて動く。
3. **入力に正直。** 全文か、抽出か、フィードの要約だけかを、アプリが示す。paywall・ログイン・robotsは回避しない。
4. **多さより軽さ。** ループを滑らかにする機能だけを足す。本人が管理するもの（フォルダ・タグ・ゴール・設定）は、できるだけ少なく保つ。

## V1に入れないもの（意図して）

ゴールや学習計画。タグや自動の分類。AIによるノートの自動編集。同期・アカウント・サーバー。Claude Desktop以外への多くの連携。

## 迷ったときの問い

1. ループ（読む・メモ・AI相談・理解）が滑らかになるのか。大きくなるだけではないか。
2. 本人が管理・判断するものが増えないか。増えるなら、既定は「やらない」。
3. 読む人を待たせることはないか。
4. 本人が読んでボタンを押さずに、文章がMacの外へ出ることはないか。
5. AIを切っても動くか。
