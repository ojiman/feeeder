# 0007 サポート下限をmacOS 27.0にし、ビルド下限は26.6のまま据え置く

- 状態: 有効
- 日付: 2026-10-10
- 決定者: 本人（PdM）

## 背景

- 利用者は本人だけで、開発機はmacOS 27.0.1。最低版（26.6）の実機確認は、これまでの検証記録で毎回NOT_RUNとして繰り越していた。
- 2026-10-10時点で、GitHub Actionsのランナー一覧（[actions/runner-images](https://github.com/actions/runner-images)）にmacOS 27のイメージは無い。Xcode 27はpreview扱いの別イメージだけがある。
- `Package.swift` の `platforms` を27へ上げると、テスト用バイナリも27以上を要求し、macOS 26のCIランナーでは起動できない。`regression` ジョブが動かなくなる。
- 現時点で、27専用のAPIを使う予定は無い。

## 決定

- サポート下限（検証して約束する範囲）をmacOS 27.0とする。アプリの `LSMinimumSystemVersion` は27.0。
- ビルド下限（`Package.swift` とCI）はmacOS 26.6のまま据え置く。CIは26のランナーで、ビルドと回帰試験だけを検証する。
- macOS 27のSDKを要するAPIは、CIがビルドできるようになるまで使わない。必要になった場合は新しい決定記録で扱う。
- macOS 27のランナーが使えるようになったら、ビルド下限とCIを27へ上げる（別のPRで行う）。

## 影響

- 「最低macOS 26.6の実機確認」は対象外になった。これまでの検証記録の未検証項目は、PASSへ変えず、サポート範囲から外れたものとして扱う。
- 27.0の実機確認は、開発機（27.0.1）で行う。27.0と27.0.1の差は確認していない。
- CIが作るad hoc署名のアプリはmacOS 26では起動しない。配布の想定が無いため問題にしない。
- 27の挙動は、ローカル実行だけが証拠になる。結果には環境（OS・Swift）を必ず添える。
