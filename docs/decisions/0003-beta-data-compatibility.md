# 0003 ベータ中はデータ互換を保証せず、1.0から保証する

- 状態: 有効
- 日付: 2026-10-07
- 決定者: 本人（PdM）

## 背景

経緯（出典で確認できる事実）:

- PR #10より前のAGENTS.mdは、V1で保存したデータを再起動とモデル変更をまたいで保持することを求めていた。beta.2・beta.3のリリースノートも、更新のために保存データを削除する必要がないことと、保持の検証結果を記載していた。
- 2026-10-07にこの方針を変更し、ベータ間の保持の保証範囲を狭めた。同じ版での保存・再起動の保持は維持した。

本人の説明（会話での発言の要約）: まだベータの段階なので、データの保持は気にしなくてよい。1.0以降は気にしたい。

提案者の評価（事実ではない）: ベータ間の保持検証は、CIの1回あたりの実行時間（約9分のうち約4分、約44%）の使用に見合わない。

## 決定

- ベータ中は、バージョン更新をまたぐ既存データの保持を保証しない。同じ版での保存と再起動による保持は維持する。
- 1.0以降は、バージョン更新とモデル変更をまたぐ保持を保証する。
- 旧DBを開けない場合は起動エラーを表示し、自動削除・作り直しは行わない。

## 影響

- ベータ間の保持検証（`store-beta1` / `store-beta2`）をCIから外した。fixture生成スクリプトと `V1StoreUpgradeTests` は、手動のopt-in検証用に残す。
- 1.0の出荷条件: 保存スキーマを `VersionedSchema` として固定する。1.0リリースタグを起点にした保持検証をCIに組み込む（docs/specification.md §7.1）。
- 次のベータ配布時のリリースノートに、この制約を明記する。beta.2・beta.3のノートは更新後もデータの削除が不要と案内しており、この決定より前の記述である。
