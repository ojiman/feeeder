# 0008 ノートをテーマ中心に改める（0004を置換）

- 状態: 有効（[PR #21](https://github.com/ojiman/feeeder/pull/21)のマージでPdM承認）
- 日付: 2026-10-10
- 決定者: 本人（PdM）。内容は本人の指示による

## 背景

本人の説明（会話での発言の要約）:

- 描いているループは「集める（feed）→読む（read）→Starで拾う→ノートで理解を深める」。実際に使うと、ノートの利用価値がボヤけてしっくりこない。
- RSSの基本の役割は、大量の記事から、理解を深める候補をStarで拾うこと。ザッピングで集めたStarを、手元で咀嚼することが中心。さらに、関心のテーマごとに整理したい。発信は副産物で目的ではない。
- ノートの機能は、このプロダクトを特徴づける部分なので、これまでの設計には縛られず見直してよい。

実装を読んで確認した事実（調査日2026-10-10）:

- ノートの入口は時間軸（日次→週）で、Starからノートへの導線が無い。
- スクラップが保存するのは、タイトル・URL・保持中のRSS要約・短いメモだけ。
- 「残す」操作が、Star・スクラップ・週の出典採用の3段階に分かれている。
- AIは日次・週ノートの「AI入力を確認」ボタンから開く確認シートを経て、別アプリ（Claude Desktop）へ出る。返答は本人が貼り戻す。

提案者（Claude）の評価（事実ではない）: 咀嚼の単位は「今日」や「今週」ではなく関心のテーマで、時間軸ではそれが育たない。AIとの往復が遠回りで、理解を深める工程が最も弱い。

## 決定

1. 概念は**Star（拾う）**と**テーマ（整理して咀嚼する）**の2つにする。
2. 日次ノート・週の振り返り・スクラップ（`n`）・週ノートの出典採用を廃止し、テーマで置き換える。
3. テーマは、名前・「いまの理解」（自由記述）・記事（複数のテーマに入れられる）・問い（問い＋自分の答え＋根拠の記事）を持つ。
4. 記事をテーマに入れる操作は`t`キーと記事ツールバーのアイコン（ドラッグ&ドロップも候補）で、**Starとは独立**させる。Starが無くても入れられ、Starを外してもテーマには残る。「未整理のStar」は、Starが付いていてどのテーマにも入っていない記事とする。
5. テーマを開くと、中央に**[記事｜問い]**の切り替えを置く。記事は購読元やフォルダと同じ一覧と読書面、問いは問いの一覧と編集面を使う。
6. 問いは、固定の**レンズ**（前提を疑う／例外・反論／成り立つ条件／トレードオフ／自分の場合）か自由記述で立てる。端末内AIがテーマの内容に合わせてレンズを具体化する案を示せる（[決定0009](0009-on-device-ai-principles.md)）。答えと理解は本人が書く。
7. フォルダ（購読元の整理）とテーマ（関心の整理）は**別の軸**のまま分ける。左カラムは、Feeds（すべての記事・未読・Star）／テーマ（未整理のStar・各テーマ）／購読元（フォルダ・購読）の順にする。
8. テーマに入れた時点のRSS要約をテーマ側で保持し、元記事の本文期限や購読解除の後も残す。全文は従来どおり期限で削除し、復活させない。

## 置換する範囲

- [0004](0004-dogfooding-keys-and-scrap.md)のうち、日次ノートと週ノートの併存、スクラップの保存内容と`n`、週候補の基準（Star付与日時とスクラップ保存日時）、日次ノートの日とタイムゾーンの固定を置き換える。`j/k/s`のキー割当、Star、フォルダ操作、Favicon・記事画像の判断は引き続き有効。
- [0005](0005-v1-product-decisions-2026-10-04.md)のうち、週の範囲のタイムゾーン固定は、対象の週ノートが無くなるため不要になる。保持・削除、Claude連携、ソース公開の判断は有効。「ノートと出典リンクは自動削除しない」は「テーマの記録は自動削除しない」と読み替える。

## 影響

- PRD・Architectureをこのテーマ中心の契約へ改訂する（このPR）。実装は段階的に進め、実装が終わるまで現行ベータは日次・週ノートのままである。
- 既存の日次・週ノートのデータは新モデルへ移行しない（[0003](0003-beta-data-compatibility.md)：ベータ間の互換は保証しない）。旧ストアを新スキーマで開けるかは未検証で、実装の最初の試験で確かめる。開けない場合は、自動削除せず止まって本人に相談する。
- 実装が切り替わる間、Claude連携の入口（日次・週ノートの「AI入力を確認」）は一時的に無くなり、テーマからの入口へ付け替えて戻す。
- 1.0のスキーマ凍結（PRD §7.1）より前に決める。時間軸の振り返りは、必要が確認されたときの候補（PRD §8）へ戻す。
