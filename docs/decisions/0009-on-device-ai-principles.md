# 0009 AIは端末内の提案に限る

- 状態: 有効（[PR #21](https://github.com/ojiman/feeeder/pull/21)のマージでPdM承認）
- 日付: 2026-10-10
- 決定者: 本人（PdM）。内容は本人の指示による

## 背景

本人の説明（会話での発言の要約）: 理解を深める工程でAIに手伝わせたい。アプリ内のBYOK（自分のAPIキー）も案として挙がったが、読書履歴や関心のテーマが外に出ることを利用者が警戒するのではないか。端末内のFoundationModelsを使うのがよい。対応OSは27以上でよい（[0007](0007-support-floor-macos-27.md)）。

検証した事実（spike（Git履歴）。合成データのみ）:

- 端末内モデルは日本語を含めて利用でき、コンテキスト窓は4096トークン（1件あたり約57トークン）。
- LLMに一括でテーマ分けさせると純度0.57、1件ずつ振り分けさせると全件が1テーマになった。日本語の文脈埋め込みで機械的に束ねると、閾値0.15で純度0.97だった。
- 構造化出力の文字列欄での名前付けは、18件中11件で不要な文章が混入した。プレーンテキストと出力上限では12件すべて正常だった。正規表現ガイドは使えなかった。
- 問いの生成は、約3分の1が考えさせる問いで、残りは言い換えか文法の崩れだった。ガードレールの誤検知エラーが出ることがある。

## 決定

1. **端末内のモデルだけ**を使う（FoundationModels、NaturalLanguage）。外部通信、アカウント、APIキー、BYOK、Private Cloud Computeを使わない。
2. AIは**提案だけ**を出す。出力は編集できる下書きで、「自分の答え」と「いまの理解」には自動で書き込まない。採用・編集・破棄は本人が決める。
3. **失敗しても手動で続けられる**。モデルの利用不可、ガードレールの誤検知、入力量の超過、システム資産の未取得では、提案が出ないだけにする。レンズの問いは、AIの具体化が無くても定型文にテーマ名を差し込んで使える。
4. **アプリが自動で通信を起こさない**。システム資産の取得要求をアプリが自動で行わない。
5. Settingsで端末内AIを無効にできる。通信が起きないため、既定は有効にする。
6. 入力量には上限がある。1回に渡すのはタイトルと切り詰めた要約で約20件までとし、超える分は新しい順に使う。提案に使った件数を示す。期限切れの全文はAI入力に復活させない。
7. 役割を分ける。記事を束ねるのは埋め込み、テーマ名はプレーンテキストと出力上限、レンズの具体化は1回1問とする。構造化出力の自由文字列欄と正規表現ガイドには頼らない。
8. 端末の外へ内容が出る経路は、本人が内容を確認して送信する既存のClaude Desktop連携だけとする（PRD §5）。

## 影響

- BYOKとAIの自動送信は、PRD §6の対象外のまま。端末外のAI（BYOK、Private Cloud Computeなど）を採用する場合は、新しい決定記録で扱う。
- 実装は、`ThemeAssistant`のプロトコルで実物のモデルを抜き、テストは偽の実装で行う。実物の出力の質は、環境を添えた検証記録に残す。
- AIの出力は実行ごとに変わるため、「PASS」は仕組み（失敗時のフォールバック、自動書込みをしないこと）に対して付け、出力の質は別に判断する。
