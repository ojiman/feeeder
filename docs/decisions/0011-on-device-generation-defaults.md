# 0011 端末内の生成（テーマ名の案・問いの具体化）の既定

- 状態: 有効（[PR 7の計画 #31](https://github.com/ojiman/feeeder/pull/31)のマージでPdM承認。計画冒頭の7点）
- 日付: 2026-10-10
- 決定者: 本人（PdM）が計画をマージして承認。内容は[決定0009](0009-on-device-ai-principles.md)・[0010](0010-on-device-suggestion-defaults.md)を実装に落とす際の選択

## 背景

0009は、AIを端末内の提案に限り、失敗しても手動で続けられること、構造化出力の自由文字列欄に頼らないことを定めた。PR 7はテキスト生成（`FoundationModels`）の最初の実装で、細部の選択が必要になった。判断基準はユーザー体験の最大化。

## 決定

1. **案は別のカードに出し、自動では何も書き換えない**。レンズを選ぶと定型の問いがすぐ入り、約1秒後に「AIの案」が出て、「採用」を押したときだけ問いの文が置き換わる（「別の案」「閉じる」もある）。まとまりの名前は、入力欄を空のまま、下に「案: …［使う］」を出す。
2. **名前の案は、まとまりからテーマを作るときだけ**。`t`での新規作成・既存テーマの名前変更では出さない。
3. **問いの案は、問いがまだ定型の文のままのときだけ**。本人が直したら出さず、出ていた案も消す。「自由に書く」では出さない。
4. **出力の検査**: 名前は先頭の1行のみ・番号・引用符・「テーマ名:」を外し・閉じ括弧・引用符・`}`より後ろを切り・2〜24文字。問いは先頭の1行のみ・10〜80文字・疑問で終わるもの（「〜か」には「。」を補う）。全体を囲む引用符の対だけを外す（定型の問いは「「テーマ名」…」で始まるため）。満たさなければ案を出さない。
5. **入力**: まとまり・テーマの記録のうち新しい16件まで、タイトル＋要約を120文字に切ったもの（決定0009の約20件より控えめ。4096トークンに収める）。テーマに記録した要約だけを使い、期限切れ全文は使わない。
6. **10秒で打ち切る**。失敗・ガードレール・上限超過・取消・期限切れはどれも「案なし」で、エラーを見せない。`LanguageModelSession.GenerationError`（macOS 27で非推奨）は型で受けない。
7. **スイッチは1つ**（Settingsの「端末内AI」）。切ると生成も可否の確認も呼ばない。Settingsには、埋め込みとは別に、名前・問いの案の状態を出す。

## 影響

- プロンプトと検査はコード（`SuggestionPrompts`・`SuggestionText`）とテストが正で、変えるときは本記録を直す。
- 生成の案には、「提案に使った件数」の表示（PRD §5.1）を出さない。プロンプトの上限（16件）を超える入力は新しい順に切るだけで、画面には示さない。必要になれば別PRで足す。
- プロンプトに入れた記事の内容は、ログにも保存にも残さない。

## 未確認

- 案の質。特に、問いが指定した角度（前提・トレードオフなど）に沿わないことが多い。質の判断は本人に委ね、PASSは仕組み（失敗しても止まらない・自動で書かない）に付ける。
- 実データでの傾向、ガードレールの誤検知の頻度、案の到着と本人の入力が重なる実機の挙動、IME・VoiceOver。
