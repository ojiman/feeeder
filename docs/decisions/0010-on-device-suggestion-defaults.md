# 0010 端末内の提案（近いテーマ・まとまり）の既定

- 状態: 有効（[PR 6の計画 #29](https://github.com/ojiman/feeeder/pull/29)のマージでPdM承認。計画冒頭の7点）
- 日付: 2026-10-10
- 決定者: 本人（PdM）が計画をマージして承認。内容は[決定0009](0009-on-device-ai-principles.md)を実装に落とす際の選択

## 背景

0009は、AIを端末内の提案に限り、失敗しても手動で続けられることを定めた。PR 6はその最初の実装（近いテーマ・まとまりの提案）で、細部の選択が必要になった。判断基準はユーザー体験の最大化。

## 決定

1. **`t`の選択**: 入力が空のとき、近いテーマを先頭に並べ、「近い」の印を付ける。既定のハイライトは先頭の行のまま。提案が届く前に入力・↑↓・操作をしていたら並びを変えない。
2. **まとまりの提案**: 「未整理のStar」を開くと、0.5秒待ってからバックグラウンドで自動計算する。未整理が3件未満なら何もしない。提案帯を開くまで何も起こさない。
3. **中心化**: 平均ベクトルを引く基準に、ライブラリの新しい記事40件を足す（少数件でも平均が安定するように）。
4. **数値**（`SuggestionTuning`に集約）: 類似度の閾値は、まとまり・近いテーマとも0.15。未整理は新しい120件まで、テーマごとの比較対象は新しい10件まで、近いテーマは上位3つ、まとまりは上位5つで、2件未満の塊は出さない。
5. **言語**: 日本語（かなを含む文、漢字だけの見出しで認識器が中国語と判定した文を含む）は日本語の文脈埋め込み、ラテン文字の言語は別のモデルを使い、**空間が違う記事どうしは比べない**。それ以外の言語は対象にしない。**1つの空間に6件未満しか無いとき（平均を引くと、少数の組はどれも反対向きに見えるため）は、その空間の記事を提案の対象から外す**。日本語中心のライブラリでは、英語の記事が6件そろうまで英語の提案は出ない。
6. **設定**: 既定は有効。Settingsの「端末内AI」で切れ、切ると可否の確認も含めてモデル・埋め込みを呼ばない。資産が端末に無い場合、アプリは取得を要求しない（ソースに`requestAssets`が無いことを試験で守る）。
7. **名前**: まとまりから作るテーマの名前は本人が入力する（名前の提案はPR 7）。

## 影響

- ベクトルは保存せず、プロセス内でのみ短期にキャッシュする。
- 閾値・上限・背景の件数は、実データの検証で変えうる。変えるときは`SuggestionTuning`と本記録を直す。

## 未確認

- 本人の実際のStarでの精度、閾値の妥当性、数百件での速度とメモリ。
- 英語・混在記事の質。資産が無い環境・Apple Intelligenceが無効な環境の実機での挙動。
- IME・VoiceOver・複数ウィンドウ。
